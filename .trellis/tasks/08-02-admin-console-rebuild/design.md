# 设计：2048 Next 管理后台

## 产品定位与视觉方向

后台定位为“2048 运营控制台”，服务高频查人、查记录、处理异常和追溯操作，不是普通玩家页面的放大版。

视觉采用克制的工业工作台风格：深石墨导航轨、暖灰纸面内容区、琥珀色高亮和 2048 方块比例的指标卡。保留项目已有的温暖色系，但提高信息密度、层级和状态辨识度。页面记忆点是仪表盘顶部的“状态方块带”，而不是通用 SaaS 式紫色渐变卡片。

不引入 React、Vue 或 Tailwind。后台基础 UI 确定采用 Tabler，并沿用现有 Vite/TypeScript 入口和本地字体栈；动画限于导航切换、抽屉与状态反馈，并遵循 `prefers-reduced-motion`。

## 开源后台框架评估

评估基于 2026-08-02 的官方仓库与 npm 包信息，并按当前 `2048-next` 的纯 Vite/TypeScript、零运行时依赖和单独 `admin.html` 入口筛选。

| 候选 | 当前形态 | 适配度 | 结论 |
| --- | --- | --- | --- |
| [Tabler](https://github.com/tabler/tabler) | MIT，`@tabler/core` 1.4.0，Bootstrap 5.3、HTML/CSS、ESM | 高 | 推荐；现代、数据密集组件完整，能够只在 Admin 入口加载 |
| [AdminLTE](https://github.com/ColorlibHQ/AdminLTE) | MIT，4.1.0，Bootstrap 5.3、原生 JavaScript、无 jQuery | 中高 | 可作为第二选择；后台壳最直接，但默认视觉更传统、结构类耦合更强 |
| [CoreUI Free](https://github.com/coreui/coreui-free-bootstrap-admin-template) | MIT，Bootstrap 5，HTML/SCSS/JS | 中 | 组件完整，但 Free/Pro 边界较多，当前需求没有明显收益 |
| [Flowbite Admin](https://github.com/themesberg/flowbite-admin-dashboard) | MIT，Tailwind 4 | 低 | 会引入 Tailwind 构建与第二套样式体系，不适合当前仓库 |
| [React Admin](https://github.com/marmelab/react-admin) / [Refine](https://github.com/refinedev/refine) | MIT，React 数据后台框架 | 低 | CRUD 能力强，但需要 React、路由和查询层重写，超出 Next 当前架构 |

### 已选方案：Tabler 作为后台基础层

- 安装并固定 `@tabler/core`，只从 `src/entries/admin.ts` 引入，不影响游戏、账户和其他页面的产物。
- 直接复用垂直导航、顶部栏、卡片、表格、表单、徽章、标签页、分页、下拉菜单、模态框和窄屏导航。
- `admin.html` 不再加载用于玩家页面的 `main.css` 与 `palette_page.css`；避免 Tabler 与旧全局样式互相覆盖。
- `style/admin_page.css` 只承担 2048 品牌变量、状态方块带、盘面预览、数据密度和少量响应式覆盖，不再自建一整套按钮、表单、表格与导航组件。
- 不复制 Tabler 的完整 Demo 工程，不采用其构建脚本，不引入演示页、图表库或额外插件。
- 所有资源经 Vite 打包为同源文件，符合当前 CSP，不使用 CDN。

### 取舍

- 收益：后台壳与基础控件可直接复用，响应式、暗色模式、焦点状态和组件一致性成本明显降低。
- 成本：新增 Bootstrap/Tabler 依赖，Admin 首屏 CSS 体积高于完全定制方案，需要用独立入口避免污染其他页面。
- 若拒绝框架：可以继续原生实现，但需要自行维护侧栏、表格、分页、菜单、对话框、窄屏抽屉和可访问性细节，实施周期与长期维护面都会更大。

## 页面框架

### 桌面端

```text
┌──────────────┬───────────────────────────────────────────────────┐
│ 2048 ADMIN   │ 全局用户搜索        环境状态       当前管理员      │
│              ├───────────────────────────────────────────────────┤
│ 总览         │ 页面标题 / 面包屑                    页面级操作     │
│ 用户与游戏   │                                                   │
│  用户中心    │ 主内容区                                          │
│  游戏记录    │                                                   │
│ 运营         │                                                   │
│  成就管理    │                                                   │
│  恢复单      │                                                   │
│ 治理         │                                                   │
│  权限 / 审计 │                                                   │
│ 系统工具     │                                                   │
│              │                                                   │
│ 身份与退出   │                                                   │
└──────────────┴───────────────────────────────────────────────────┘
```

- 侧边栏宽约 232px，页面滚动时保持固定。
- 顶栏固定在内容区顶部，包含全局用户搜索、API 状态和当前身份。
- 内容最大宽度不锁死在窄列；表格页使用可用宽度，详情页控制在约 1280px。
- URL 使用 `admin.html?view=<module>`，详情使用 `&user=<id>`、`&record=<id>` 等参数，支持刷新与分享。

### 窄屏

- 侧边栏收进左侧抽屉，顶栏保留菜单、搜索和当前页面标题。
- 指标卡两列或单列；用户列表切换为摘要卡，详情操作放入底部固定操作区或菜单。
- 只有数据表自身允许横向滚动，页面根节点不得横向溢出。

## 核心页面

### 1. 仪表盘

- 第一行状态方块：总用户、启用账户、近 7 日新增、近 7 日活跃。
- 第二行运营卡：待处理恢复单、异常记录、最近管理员操作。
- 下方双列：最近注册用户、近期警告/错误事件。
- 每个指标均可进入已带筛选条件的目标模块。

### 2. 用户中心

列表顶部包含搜索、角色、状态、活跃时间和排序。默认列：用户、角色、状态、注册时间、最近登录、最近活跃、记录数、操作。

点击用户进入详情：

```text
┌───────────────────────────────────────────────────────────────┐
│ 头像  昵称 / 邮箱 / #ID    状态与角色          高风险操作菜单 │
│       注册、登录、活跃时间                                      │
├───────────────────────────────────────────────────────────────┤
│ 概览 │ 游戏记录 │ 成就与恢复 │ 活动记录                         │
├───────────────────────────────────────────────────────────────┤
│ 当前分区内容                                                   │
└───────────────────────────────────────────────────────────────┘
```

- 概览：身份资料、账户状态、统计摘要、各模式最佳成绩。
- 游戏记录：该用户记录、回放、校验与排行榜状态。
- 成就与恢复：已获成就、手动发放入口、恢复单历史与签发入口。
- 活动记录：该用户相关审计日志和运行异常。
- 高风险操作收在统一菜单，不在页面各处重复按钮。

### 3. 游戏记录

- 全局记录表支持用户、模式、状态、记录 ID 和时间筛选。
- 记录详情采用右侧抽屉，展示核心数值、最终盘面、校验摘要、回放与排行榜影响。
- “隐藏记录”确认框明确说明会重算排行榜；恢复操作同样说明影响。

### 3.1 对局补录

入口同时存在于用户详情的“游戏记录”分区和全局游戏记录页。流程固定为两步：

1. 选择目标用户，上传 `.txt` / `.rpl` 回放或粘贴回放字符串，填写补录原因。
2. 服务端执行 dry-run，界面只读展示校验出的模式、分数、最大方块、步数、时长、结束时间、回放指纹和重复状态；管理员确认后才正式写入。

不提供分数、步数、盘面或时长编辑框。记录写入后显示 `source=admin` 和“管理员补录”标签，并可从审计日志追溯操作者、目标用户、原因和回放指纹。

现有 `scripts/import-user-replay-records.ts` 已具备终局回放校验、指纹去重、`client_record_id` 去重、回放对象存储和 dry-run 能力。实施时将其核心逻辑抽到后端共享模块，CLI 与 Admin API 共同调用，避免维护两套导入算法。

Admin 补录采用正式写入策略：`source=admin`、`record_era=official_v1`，事务内刷新相关排行榜，并执行与正常正式记录相同的成就评估。现有 CLI 的历史 beta 导入语义保持不变；共享核心通过明确策略参数区分“历史迁移”和“管理员正式补录”，不能静默改变旧脚本行为。

### 4. 成就管理

- 左侧可搜索成就目录，右侧编辑当前定义。
- 规则、图标和状态编辑延续现有能力。
- 手动发放与历史回填移动到独立操作区；从用户详情进入时预填用户 ID。

### 5. 恢复单

- 首屏先展示恢复单列表与筛选，签发按钮打开抽屉表单。
- 手工盘面和回放上传作为同一表单的两种来源，避免同时展示两个大型输入区。
- 用户详情跳转时自动锁定目标用户，仍允许返回全局列表。

### 6. 管理员与权限

- 展示最高权限管理员与所有超级管理员。
- 只有 ID 0 看到授予/撤销入口；受保护账户直接显示原因。
- 普通用户和板块管理员的角色调整主要在用户详情完成，本页只管理 Next 后台访问者。

### 7. 审计日志

- 一级切换：管理操作、运行事件。
- 管理操作按操作者、目标用户、动作、对象和时间筛选；变更差异使用可折叠前后对比。
- 运行事件按严重级别、用户、记录、会话和事件类型筛选。

### 8. 数据工具

- “表浏览”与“只读 SQL”分开，默认进入表浏览。
- 明确标记只读、5 秒超时和最大返回量。
- 不从用户详情或其他日常页面链接到 SQL 编辑器。

## 前端技术边界

- 保留 `admin.html` 和 `src/entries/admin.ts` 单入口，避免新增多个 Vite HTML 入口。
- `src/pages/admin-page.ts` 只负责权限门禁、URL 视图路由和页面级装配。
- 原始 API 请求统一进入新的 `src/services/admin.ts`；不在功能模块中拼接认证和错误协议。
- 按业务拆分最少模块：dashboard、users、records、achievements、rescue、governance。共享 DOM/格式化辅助保持小而直接，不建立组件框架。
- 结构化中英文字典在渲染时取值，删除现有 MutationObserver 文本替换方案。
- 复用 Tabler/Bootstrap 的 Modal、Offcanvas、Dropdown 和 Collapse 完成确认、详情抽屉和窄屏导航，不再重复实现对应交互组件。

## Admin API 设计

复用现有权限检查、事务、审计和排行榜重算逻辑，新增面向 Next 后台的受控合同：

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/admin/dashboard` | 后台指标、近期用户、异常与操作摘要 |
| GET | `/api/admin/users` | 用户搜索、筛选、排序和分页 |
| GET | `/api/admin/users/:id` | 账户资料、统计和近期关联数据 |
| PATCH | `/api/admin/users/:id/profile` | 修正昵称、显示名、头像地址 |
| PATCH | `/api/admin/users/:id/status` | 启用或停用账户 |
| PATCH | `/api/admin/users/:id/role` | 调整玩家/板块管理员角色 |
| POST | `/api/admin/users/:id/revoke-sessions` | 失效既有登录 token，不修改密码 |
| POST | `/api/admin/users/:id/password-reset` | 向账户邮箱发送安全重置验证码 |
| GET | `/api/admin/records` | 记录搜索、筛选和分页 |
| POST | `/api/admin/users/:id/record-import/preview` | 校验单条回放、计算指标并检查重复，不写入 |
| POST | `/api/admin/users/:id/record-import` | 确认写入已校验的管理员补录记录 |
| POST | `/api/admin/records/:id/hide` | 软隐藏记录并重算最佳记录 |
| POST | `/api/admin/records/:id/restore` | 恢复记录并重算最佳记录 |
| GET | `/api/admin/audit` | 管理操作审计 |
| GET | `/api/admin/events` | 游戏与运行事件查询 |

现有 `/api/admin/me`、`/super-admins`、`/achievements`、`/rescue-offers`、`/tables` 和 `/query` 保留并接入新布局。

已结束的 `/api/admin/beta-access/allowlist` 管理端点移除；历史表不删除。

## 数据与安全

- 用户列表和详情只返回后台需要的字段，绝不返回 `password_hash`、验证码、token hash、签名密钥或完整敏感运行上下文。
- 用户列表、记录和审计必须服务端分页，默认 50、最大 200。
- 强制注销通过更新目标用户的令牌失效时间并清除缓存实现，不改密码字段内容。
- 资料修改继续经过昵称敏感词、唯一性和 URL 校验。
- 记录隐藏/恢复在事务中调用最佳记录重算，并写入包含前后状态的审计日志。
- 补录复用与正常提交相同的回放验证器、存储、指纹和去重规则；客户端提供的成绩字段全部忽略。
- 正式补录在同一事务中写入记录、刷新排行榜、评估成就并写审计；任一步失败都不留下半条记录。
- 所有高风险 API 拒绝当前操作者自降权、自停用和对 ID 0 的任何破坏性操作。
- 登录、注册完成、令牌刷新和密码变更在原有 Bearer token 之外同步签发一个同源、`HttpOnly`、`SameSite=Lax` 的页面门禁 Cookie；Cookie 只供反向代理门禁使用，不授权其他 Admin API。
- Nginx 对精确 `/admin.html` 使用 `auth_request`，把门禁 Cookie 映射成 `Authorization: Bearer` 后复用现有 `/api/admin/me`，将 401/403 映射为站点 404；`admin.html` 与 404 响应均使用 `private, no-store`，防止 CDN 缓存绕过逐请求鉴权。
- 门禁因此继续复用现有 token 签名、有效期、`password_changed_at` 与超级管理员校验；`board_admin` 不通过，不新增第二套权限判断。
- 显式退出登录调用 `/api/logout` 清除门禁 Cookie，然后清理浏览器本地认证状态；API 写操作仍只接受 `Authorization: Bearer`，不扩大 Cookie 的 CSRF 权限面。

## 兼容与迁移

- 先新增 API 与新页面骨架，再逐模块迁移现有成就、恢复单和系统工具。
- 迁移期间 `/admin.html` 始终可打开；未迁移模块不应出现空导航。
- 新后台完成后删除旧卡片 DOM、旧页面渲染代码、MutationObserver 翻译和内测管理代码。
- `2048-ranked` 不需要兼容改动，也不调用新增的 Next Admin API。

## 风险与回滚

- 风险：聚合用户详情查询过重。首屏只返回摘要和少量近期数据，其余分区按需分页加载。
- 风险：记录隐藏后排行榜残留。必须在同一事务中复用最佳记录重算并用 API 测试覆盖。
- 风险：旧页面重构跨度大。保留单入口并逐模块替换，便于按提交回滚。
- 回滚：前端可恢复旧 `admin.html` 与 `admin-page.ts`；新增只读 API 可独立保留，写操作 API 若回滚前端也不会被普通用户调用。
