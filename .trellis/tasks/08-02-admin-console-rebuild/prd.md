# 2048 Next 管理后台重构

## Goal

仅重构 `2048-next` 的 `admin.html`，把当前功能堆叠式长页面升级为可独立使用的完整后台：管理员能够统一搜索所有用户，查看其账户、游戏、排名、成就、恢复单与操作记录，并在权限允许时完成安全、可审计的管理操作。

`2048-ranked` 后台继续独立存在，本任务不修改其页面、组件或交互。

## Background

- 当前 `admin.html` 同时承载权限检查、原始数据库查询、内测名单、超级管理员、恢复单和成就管理，没有后台级导航或统一用户视图。
- `src/pages/admin-page.ts` 已超过 1600 行，`admin.html` 超过 350 行；页面结构、数据请求、领域逻辑、翻译和 DOM 渲染集中在同一文件。
- `2048-game-api` 是账户、权限、游戏数据、排名、审计和 Admin API 的唯一权威；Next 前端只能负责渲染、输入状态和调用 API。
- 后端已有管理员校验、超级管理员管理、用户启停/角色、记录软删除/恢复、成就、恢复单、只读 SQL 和部分审计能力，但缺少面向 Next 后台的统一用户查询与详情合同。
- 内测已结束。Next 后台不得继续展示或维护内测资格；历史名单数据不做破坏性删除。

## Requirements

### R1. 后台框架

- 保留 `/admin.html` 作为唯一入口。
- 提供固定侧边导航、顶部全局用户搜索、当前管理员身份、主内容区和窄屏抽屉导航。
- 页面刷新、前进/后退和复制链接后仍能恢复当前模块与筛选状态。

### R2. 仪表盘

- 展示总用户、启用/停用账户、近 7 日新增、近 7 日活跃、待处理恢复单和近期异常事件。
- 提供最近管理员操作、最近注册用户和异常记录的快捷入口。
- 不把原始数据库表或 SQL 编辑器放在首页。

### R3. 用户中心

- 支持按用户 ID、邮箱、昵称搜索，并按角色、启用状态和最近活跃筛选、分页。
- 用户详情统一展示：账户资料、邮箱验证状态、角色、启用状态、创建/登录/最近活跃时间、游戏统计、排名摘要、成就、恢复单和审计记录。
- 允许管理员修正非认证资料：昵称、显示名和头像地址；登录邮箱保持只读。
- 用户详情使用“概览、游戏记录、成就与恢复、活动记录”分区，不把全部数据塞进一个表格。

### R4. 账户与权限操作

- 超级管理员可启用/停用普通用户、玩家与板块管理员之间调整角色。
- 最高权限管理员可授予或撤销超级管理员；ID 0 不可被停用、降权或撤销。
- 管理员不可修改自己会导致当前会话失效的角色或状态。
- 支持强制注销目标用户的全部既有登录会话。
- 支持向用户邮箱触发安全的密码重置流程；管理员不能查看明文密码，也不能直接设置用户密码。
- 每个高风险操作必须展示影响、要求二次确认并写入审计日志。

### R5. 游戏记录与排行榜处置

- 支持按用户、模式、状态、记录 ID 和时间筛选记录。
- 可查看记录摘要、校验状态、最终盘面、回放入口和对应排行榜信息。
- 管理员可隐藏或恢复记录；隐藏后重新计算该用户在相关模式的最佳记录与排行榜结果。
- 不允许直接修改分数、步数或回放内容，不提供永久删除记录。

### R6. 对局补录

- 管理员可从独立的“成绩补录”一级模块，为指定用户上传一份未正常上传的本地回放记录；用户详情和全局游戏记录继续提供快捷入口。
- 补录必须先进行服务端预校验，展示从回放计算出的模式、分数、最大方块、步数、时长、结束时间和重复检查结果，再由管理员二次确认。
- 后端只信任回放校验结果，不接受管理员手工填写或覆盖分数、步数、最终盘面和时长。
- 只接受完整、终局、格式合法且未超过大小限制的回放；重复回放或重复 `client_record_id` 不得再次写入。
- 补录原因必填，写入记录校验摘要和审计日志；用户记录列表明确标记“管理员补录”。
- 管理员确认写入后，补录记录按 `official_v1` 正式记录处理，参与该用户相关模式的最佳记录与排行榜重算，并触发符合条件的成就。
- 首期只处理单条回放，批量导入继续由现有 CLI 工具承担。

### R7. 成就管理

- 保留并重组现有成就定义、规则、图标、手动发放和历史回填能力。
- 支持从用户详情直接进入已预填目标用户的发放流程。
- 成就定义修改、发放和回填均写入审计日志。

### R8. 恢复单管理

- 保留手工盘面与回放文件签发恢复单的能力。
- 支持按用户、状态和时间查询恢复单；从用户详情进入时自动带入目标用户。
- 明确展示待确认、已接受、已拒绝、已使用和已过期状态。

### R9. 管理员与权限

- 独立列出所有超级管理员及其状态。
- 最高权限管理员可以授予和撤销超级管理员，其他管理员只能查看。
- Next 后台只允许最高权限管理员与超级管理员进入；`board_admin` 不能访问 Next 后台。

### R10. 审计与系统工具

- 审计日志支持按操作者、目标用户、动作、对象和时间筛选。
- 将账户操作审计与游戏运行异常放在同一模块的不同视图中，避免混淆。
- 保留允许表的数据浏览和单条只读 `SELECT`，作为“系统工具”模块；日常用户管理不得依赖手写 SQL。
- SQL 继续受单语句、只读事务、超时和表范围限制。

### R11. 内测模块退场

- 从 `admin.html`、前端脚本、样式、翻译、测试和 API 合同中移除内测资格管理入口。
- 移除不再使用的 `/api/admin/beta-access/allowlist` 管理端点及其前端调用。
- 不在本任务中删除历史名单表或历史数据，避免不可恢复的数据破坏。

### R12. 体验与兼容

- 采用 MIT 开源的 `@tabler/core` 作为后台基础 UI，只允许从 Admin 入口加载；游戏、账户和其他页面不得引入 Tabler 资源。
- 中文和英文界面均不得依赖 DOM 文本替换实现翻译；页面文案由结构化字典渲染。
- 核心操作支持键盘，表格、筛选器、抽屉、确认对话框和状态反馈具有明确标签与焦点行为。
- 桌面宽屏优先保证信息密度；窄屏允许卡片化或横向滚动，但核心用户管理流程必须可完成。
- 保留前端管理员身份二次校验；拒绝目标按 R13 统一改为 404。

### R13. 后台页面门禁

- `/admin.html` 只允许已登录的最高权限管理员或超级管理员取得页面文档；普通用户、`board_admin`、未登录、失效或已撤销会话均返回真实 HTTP 404。
- 页面门禁必须由反向代理向 `2048-game-api` 发起服务端鉴权，不得依赖浏览器 `localStorage` 或仅靠前端跳转隐藏。
- 管理员页面与门禁失败响应不得被浏览器或 CDN 公共缓存；显式退出登录必须同步清除页面门禁凭证。
- 前端仍保留 `/api/admin/me` 二次校验，在本地开发服务器或未启用反向代理门禁的环境中失败时回退到 `404.html`。

## Acceptance Criteria

- [ ] A1：打开 `/admin.html` 后可通过稳定导航进入仪表盘、用户、记录、成绩补录、成就、恢复单、管理员与权限、审计和系统工具。
- [ ] A2：管理员可在三次交互内从全局搜索进入任一用户详情，并看到该用户账户及全部纳入范围的关联数据。
- [ ] A3：账号停用/启用、角色调整、强制注销、触发密码重置、记录隐藏/恢复、成就发放和恢复单签发均有确认、结果反馈和审计记录。
- [ ] A4：最高权限与超级管理员的操作边界符合 R9；受保护账户和当前登录账户不能被错误处置。
- [ ] A5：隐藏或恢复记录后，相关最佳记录与排行榜结果同步重算，刷新页面结果保持一致。
- [ ] A6：日常用户管理不需要 SQL；原始数据和 SQL 只出现在系统工具。
- [ ] A7：页面中不存在内测资格卡片、导航、请求或可执行管理端点，历史数据未被删除。
- [ ] A8：`2048-ranked` 没有产品代码改动，其现有后台行为保持不变。
- [ ] A9：桌面与窄屏均可完成用户搜索、查看详情和至少一个高风险操作；无横向页面级溢出。
- [ ] A10：目标单测、Admin Smoke、API 测试、类型检查、服务边界审计和生产构建通过。
- [ ] A11：生产构建中 Tabler 资源只被 Admin 入口引用，其他页面的启动资源和行为保持不变。
- [ ] A12：管理员上传合法回放后先看到预校验结果；确认补录后记录出现在目标用户下、参与排行榜重算并触发符合条件的成就，非法或重复回放不会产生记录，并且操作可审计。
- [x] A13：生产反向代理下，只有有效管理员会话访问 `/admin.html` 返回 200；其他身份返回 404，且成功与失败响应均不可被公共缓存，退出后立即失去页面访问权。

## Out of Scope

- 修改、迁移或退役 `2048-ranked` 后台。
- 查看明文密码、管理员直接设置密码、永久删除用户或永久删除游戏记录。
- 直接修改已验证记录的分数、步数、盘面或回放。
- 首期后台批量补录、多用户批量导入或没有回放文件的手工成绩补录。
- 通用站点配置中心、功能开关平台或新的权限框架。
- 删除历史内测名单表和数据；其彻底归档可另开数据治理任务。

## Key Decisions

- 两套后台长期并存，本任务只重构 `2048-next`。
- Next 后台仍使用单一 `admin.html` 入口，但内部成为可深链接的多模块工作台。
- “所有权限”遵循安全边界：允许管理和处置，不暴露密码、不硬删除、不直接篡改成绩。
- 内测资格功能退出后台，但保留历史数据。
- 后台基础 UI 采用 `@tabler/core`；只复用框架壳和基础组件，不复制 Demo 工程、不引入 React/Tailwind，也不把资源加载到其他页面。
- 合法的管理员补录与正常成功上传等价：写入 `official_v1`、参与排行榜和成就；来源保持 `admin`，原因和操作者可审计。

## Risks and Deferred Items

- 当前账户、游戏和审计数据分布在多张表，新 Admin API 必须使用受控查询聚合，不能把任意 SQL 暴露给日常页面。
- 强制注销将复用现有 `password_changed_at` 令牌失效机制；实施时需保证不改变用户密码本身。
- 记录处置会影响排行榜，必须复用现有最佳记录重算逻辑，避免只改记录状态。
- 旧后台全部在一个脚本中，迁移期间需要保留入口可用并按模块逐步替换，最后再删除旧 DOM 和死代码。
- Tabler 主样式体积高于完全定制方案；必须通过 Admin 独立入口、生产构建检查和资源预算审计限制影响范围。
- 管理员补录绕过了正常客户端排位会话来源校验，因此必须依赖完整回放验证、权限、强制原因和审计；不得提供任何成绩字段覆盖能力。
