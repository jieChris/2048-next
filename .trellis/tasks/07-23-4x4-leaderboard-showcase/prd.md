# 经典 4×4 无撤回测试排行榜

## 目标

新增一个与现有 `account.html` 完全独立的测试排行榜页面，用于验证 Trophy 官网参考图中的黑色游戏化仪表板与紧凑排名列表是否适合 2048 Next。

## 已确认事实

- 现有多模式排行榜必须保持原样，不改入口、筛选、排序或渲染。
- 新页面只展示 `standard_4x4_pow2_no_undo` 的正式、已验证排行榜数据。
- 当前前端是原生 HTML/TypeScript/CSS，不使用 React、Tailwind 或 shadcn。
- Trophy UI 采用 MIT 许可，但本次只参考信息层级和布局，不复制其 React 源码。
- 排行榜权威排序属于 `2048-game-api`，前端不得自行计算权威名次。
- 现有 `/api/leaderboard` 没有 `board_sum`，且同分规则与本测试榜不同；不能修改其行为影响现有页面。

## 需求

- 新增独立页面 `leaderboard_4x4.html`，测试阶段不加入正式导航。
- 页面只有经典 4×4 无撤回总榜，不提供模式、撤回、周期或指标筛选。
- 页头使用与首页一致的 `meta/logo-tall.png` 品牌标志，不保留页面自制 Logo。
- 页面提供参考图对应的白色仪表板，并在全局夜间背景启用时切换为深青黑专业版；两套外观均保留金色前三名点缀与紧凑排行榜行，不再使用大尺寸前三名领奖台。
- 页面移除左侧大标题与说明，仅保留数据概览和排行榜单列，并在桌面端水平居中。
- 桌面端在主榜右侧增加 260px 补充栏，复用现有数据展示经典里程碑、前三名迷你领奖台和成就墙入口；登录用户的底部进度卡展示完成度最高的未完成经典4×4里程碑成就，完成后自动切换，未登录时保留 32768 全局达成率；窄屏按主榜、补充栏顺序纵向排列。
- 第 1—10 名使用同一紧凑列表结构，前三名显示小面积金/银名次标记，当前用户使用亮色描边。
- 保留头像槽位；当前没有头像时显示昵称首字占位，不接入外部随机头像服务。
- 以分数为唯一主排名值并显示精确整数，不使用 `k`/`m` 缩写。
- 每位玩家同时显示最大方块、盘面和与用时作为辅助信息。
- 同分排序依次为：分数降序、最大方块降序、盘面和降序、用时升序、上传时间升序。
- 当前登录用户若出现在返回的前十名中，行/领奖台需要高亮。
- 昵称和头像槽位可跳转到现有用户主页；没有有效用户 ID 时不可跳转。
- 页面提供加载中、空数据、失败和手动刷新状态。
- 页面响应式支持桌面与窄屏，并沿用当前主题变量与夜间模式。
- 后端新增只读的固定榜单接口，复用现有正式已验证记录，不改变现有 `/api/leaderboard`。
- 排行榜上方增加与参考图一致的数据概览区，但不虚构 XP、任务或签到体系：
  - 正式对局数；
  - 去重参赛玩家数；
  - 达到 16384 的正式对局数与占比；
  - 达到 32768 的正式对局数与占比；
  - 北京时间最近 7 天每日最高分趋势；
  - 当前榜首分数与第 10 名分数作为趋势图参考线。

## 验收标准

- 打开 `leaderboard_4x4.html` 时只请求固定的经典 4×4 无撤回展示接口。
- API 返回的前十名严格符合已确认的同分规则，并包含 `score`、`max_tile`、`board_sum`、`duration_ms`。
- API 同时返回上述全局概览与连续 7 个北京时间日期的趋势数据；无对局日期返回 0，不跳过日期。
- 有效登录令牌存在时，API 额外返回当前用户未完成的经典4×4里程碑中完成度最高的一项；全部完成时返回完成状态，无令牌或令牌无效时不返回个人进度。
- 页面按第 1—10 名顺序显示紧凑列表；当前用户在前十时具有与参考图一致的明确描边高亮。
- 头像为空时不发生外部图片请求，显示本地首字占位。
- API 错误时页面保留结构并显示可重试状态。
- 现有 `account.html`、`js/account_page.js` 与 `/api/leaderboard` 行为没有改变。
- 前端构建、目标单元测试和 Playwright Smoke 通过；后端目标 Node 路由测试通过。

## 暂不纳入

- 真实头像上传、裁切、存储与审核。
- 日榜、周榜、月榜、赛季榜或往期榜。
- 可撤回模式及其他棋盘/规则模式。
- 替换或链接到现有多模式排行榜。
- 为前十以外的当前用户单独计算和显示名次；有明确需求时再扩展接口。
- 独立 XP、任务、签到或连续登录系统。

## 开放问题

- 无阻塞问题；用户已明确要求开始实现。

## Route Deviation

- 仓库缺少 `.trellis/scripts/task.py` 与 `.trellis/scripts/get_context.py`，无法使用标准任务创建和上下文发现命令；采用最保守回退，手工创建任务目录并直接读取两个仓库的 `AGENTS.md` 与 `.trellis/spec/*`。
