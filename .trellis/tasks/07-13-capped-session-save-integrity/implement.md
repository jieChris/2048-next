# 1024 封顶模式存档完整性

## 目标

- 排位会话过期、认证状态变化或浏览器反复关闭重开时，仍保留最后一次本地棋盘进度。
- 本地恢复不得选择比已持久化棋盘更旧的 checkpoint 镜像。
- 新排位会话不得静默覆盖属于旧会话但仍可本地继续的棋盘。

## 实施顺序

1. 追踪启动时 active session、完整存档、轻量存档、window.name 与 checkpoint 镜像的选择顺序。
2. 添加 1024 封顶模式的失败回归，覆盖会话失效、关闭页面、重建页面和连续重载。
3. 在共享持久化边界实施最小修复，不改变服务端排位校验规则。
4. 运行目标单元测试、目标 Smoke、相关关键 Smoke、完整单元测试与构建检查。

## 验收标准

- 两个 1024 所在棋盘在连续关闭重开后保持不变。
- 分数、移动记录和存档时间不回退。
- 会话过期最多影响排位提交资格，不得删除或重置本地在局棋盘。
- 非排位模式、正常新开局和显式重新开始行为保持不变。
