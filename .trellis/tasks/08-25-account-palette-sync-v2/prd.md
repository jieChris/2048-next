# 账号私人色板同步 V2 PRD

## 1. 背景

当前生产系统有 `user_app_palettes` 账号整库 JSON、`/api/me/app-palettes` GET/PUT 和 Web 侧临时接入的整库 repository，但它们不构成完整的账号色板云同步产品：

- Web 仅在色板页和主题广场页读取云端；其他页面登录不会恢复账号最后应用色板。
- 整个 `palettes[]` 共用一个 revision，不同设备修改不同色板也会产生整库冲突。
- 当前上限错误地实现为八套，目标是十套自定义色板且不包含内置色板。
- 当前色板选择只能被旧 `activePaletteId` 不完整表达，无法可靠表示跟随主题和内置色板。
- Theme Plaza 把整库 dirty/conflict 当作当前色板分享资格，导致无关色板状态阻止分享。

生产 Theme Plaza 已执行安全关闭：公开浏览保持开放，写入和自动发布关闭，直到本 PRD 的门禁完成。

## 2. 目标

1. 每个账号保存最多十套私人自定义色板，不包含内置色板。
2. 每套自定义色板使用跨设备稳定 ID 和独立权威 revision。
3. 当前色板选择独立保存，可指向跟随主题、任一内置色板或一套云端自定义色板。
4. 每个登录会话只读取一次当前选择；只有当前选择指向自定义色板时才下载该套内容。
5. 完整私人色板库只在进入设置或其他管理界面时延迟加载。
6. 创建、保存、删除、排序和选择变化按操作定向写回，不轮询、不上传整库。
7. 多设备同套编辑由服务端三方合并，无法无损合并时自动保留冲突副本。
8. 删除使用永久删除标记，旧设备不能复活原 palette ID。
9. Theme Plaza 仅依据当前选中色板自身状态判断分享和保存资格。
10. 旧整库数据、旧 GET 和旧标签页可以安全迁移，不允许旧 PUT 破坏新模型。

## 3. 非目标

- 第一阶段不提供玩家可见的私人色板历史版本恢复 UI。
- 不进行后台定时轮询。
- 不在客户端执行权威合并或容量裁决。
- 不自动删除旧色板、冲突副本或本地待上传色板。
- 不改变 Theme Plaza 已发布版本的不可变快照和历史引用事实。

## 4. 领域模型

权威术语见仓库根目录 `CONTEXT.md`。核心关系：

```text
账号
├── 私人色板库（最多 10 套有效自定义色板）
│   ├── 权威色板记录 A
│   │   ├── revision 1
│   │   ├── revision 2
│   │   └── 当前 revision
│   ├── 权威色板记录 B
│   └── 永久删除标记
├── 当前色板选择
└── 正式色板顺序

账号
└── Theme Plaza 作品槽位（最多一个公开版本 + 一个候选）
```

稳定 palette ID 表示身份；内容哈希只表示内容相同。不同 ID、相同内容的色板可以共存并分别占用名额。

## 5. 产品行为

### 5.1 登录会话首同步

每个登录会话只执行一次：

1. 读取账号当前色板选择。
2. 选择为 `follow-theme` 或内置色板时，不下载私人色板库。
3. 选择为自定义色板时，只下载该稳定 ID 的当前内容。
4. 使用设备账号缓存立即启动页面；云端结果到达后校正。
5. 同一会话内页面跳转不重复读取；浏览器重启并恢复登录后开启新会话首同步。
6. API 不可用时使用本地缓存，不阻塞游戏启动。

普通旧缓存不能覆盖云端选择；账号绑定的离线选择操作恢复联网后写回；游客当前选择不覆盖账号选择。

### 5.2 设置页延迟加载

进入设置页后才读取：

- 全部有效私人色板；
- 正式色板顺序；
- 当前设备绑定该账号的本地待上传色板；
- 重复确认状态；
- 单套同步状态。

本地当前自定义色板在登录首同步时可以立即处理；其他本地色板等设置页加载后再与云端按稳定 ID 对账。

### 5.3 编辑与保存

- 编辑器产生 `色板编辑草稿`，只影响设置页预览。
- 草稿不改变游戏、其他页面、云端版本或 Theme Plaza 分享内容。
- 玩家点击保存后才冻结完整规范化内容并创建一次 `色板保存操作`。
- 网络在线时立即定向写回；网络不可用时持久保存到本设备并进入原账号离线队列。
- 保存结果必须区分“已同步到账号”和“已保存到此设备，等待同步”。
- 任何会丢失编辑上下文的操作显示“保存并继续 / 放弃修改 / 取消”；刷新或关闭标签页使用原生离开确认。

### 5.4 当前选择和排序

当前选择与正式顺序是两个独立资源：

- 当前选择：最后一次成功写入生效。
- 正式顺序：最后一次成功排序生效。
- 新上传或从广场保存的色板追加到末尾。
- 冲突副本紧邻原色板；本地待上传和重复确认在独立区域展示。
- 当前自定义色板被删除时，账号选择原子回退到 `follow-theme`。
- 云端选择不能指向不存在、已删除或尚未上传的自定义色板。

### 5.5 离线操作队列

队列绑定账号并按稳定 palette ID 折叠：

- 未上传的创建 + 多次修改：提交一次最终创建。
- 未上传的创建 + 删除：本地取消，不写云端删除标记。
- 已同步色板 + 多次修改：只提交最终快照。
- 已同步色板 + 修改 + 删除：删除优先。
- 执行顺序：色板创建/保存/删除 → 正式顺序 → 当前选择。
- 当前选择指向新色板时，必须等待色板上传成功。
- 短暂失败有限重试；随后保持待写回，等待网络恢复、设置页加载或新登录会话。
- 认证失败暂停原账号队列，绝不迁移到其他账号。

### 5.6 容量与重复内容

- 服务端在账号级事务锁内统计有效色板，最多十套。
- 删除标记不占名额。
- 两设备并发创建第十套时，先提交成功者占位；后到色板保留为本地待上传。
- 满库时绝不覆盖或自动删除旧色板。
- 内容相同、ID 不同的色板允许共存并分别占位。
- 自动导入或广场保存发现重复内容时，默认提供“使用已有色板”，也允许玩家选择“仍然保留为新色板”。后台发现重复时进入设置页可处理的重复确认状态，不突然弹窗。
- 同一 operation ID 的网络重试直接返回原结果，不产生重复身份。

### 5.7 删除与长期离线

- 已同步色板删除后保留永久删除标记。
- 旧设备没有离线修改时移除本地副本。
- 旧设备在删除后离线修改时，不复活原 ID；修改内容使用新稳定 ID，满库则本地待上传。
- 当前选择指向被删除色板时回退 `follow-theme`。

### 5.8 多设备三方合并

客户端提交：稳定 ID、base revision、完整规范化色板、operation ID。服务端读取 base、current 和 incoming，按最小用户可编辑单元比较：

- 只有 incoming 改动：采用 incoming。
- 只有 current 改动：保留 current。
- 双方改成同一值：采用该值。
- 双方修改不同单元：自动合并。
- 双方修改同一单元为不同值：原 ID 保留当前云端，incoming 创建冲突副本。

合并单元包括名称、基础皮肤、每个规则族/等级的背景、文字、边框、发光、整体发光强度和每个倍率。设备字段和时间戳不参与内容冲突。

共同版本已被清理时：内容相同视为成功；原 ID 已删除则创建新 ID；其他不同内容创建冲突副本。满库时副本留在本地待上传。

### 5.9 版本历史

- 每次接受有效内容变化创建不可变完整快照。
- 内容未变化和幂等重试不创建新 revision。
- 保留最近 100 个 revision 与最近 180 天 revision 的并集。
- 当前 revision 和删除标记始终保留。
- 第一阶段仅供合并、恢复和审计，不提供历史 UI。

### 5.10 Theme Plaza

公开浏览保持开放。写能力拆分为：

- 互动：点赞、点踩、举报；
- 保存：从公开版本创建一套私人色板；
- 分享：提交、更新、撤回作者作品；
- 自动发布：独立审核门禁。

分享只检查当前选中色板：它必须是已存在于云端、没有未保存草稿、没有待写回修改、未删除的自定义色板。其他色板的失败、待上传、重复确认或排序状态不得阻止分享。

## 6. API 合同目标

具体 OpenAPI 由首个合同 ticket 冻结，至少提供：

```text
GET    /api/me/palette-sync/bootstrap
GET    /api/me/palettes
GET    /api/me/palettes/:paletteId
POST   /api/me/palettes
PUT    /api/me/palettes/:paletteId
DELETE /api/me/palettes/:paletteId
GET/PUT /api/me/palette-selection
GET/PUT /api/me/palette-order
```

写请求携带 operation ID；保存携带 base revision 和完整色板。响应明确区分：saved、merged、conflict_copy、duplicate_existing、capacity_full、deleted、base_revision_expired。

旧 `GET /api/me/app-palettes` 在切换后从新模型组装只读兼容 document：active 色板数不超过 8 时返回投影；达到 9–10 时返回 `PALETTE_SYNC_CLIENT_UPGRADE_REQUIRED`，绝不静默截断。旧 PUT 在切换完成后先于请求体解析和 revision 查询返回同一升级码，不接受整库覆盖。

### 6.1 已冻结合同决策

- **Canonical contract**：`2048-next/openapi/2048next.v1.yaml` 是唯一来源；API CI 通过锁文件记录 Web commit、SHA-256 和合同版本，并校验同一摘要。
- **Stable ID**：普通/离线创建使用客户端生成的小写 UUID v4；服务端冲突副本使用服务端生成的小写 UUID v4。账号内永久唯一，tombstone ID 不可复用。
- **Operation ID**：账号内唯一 UUID。第一次网络发送后 ID 和请求哈希冻结；后续编辑使用新 operation。完整响应保留 400 天，过期重试必须重新对账。
- **内容归属**：权威视觉字段由合同明列；服务端字段不可由客户端写；`source`、`locked` 和 UI 状态为设备私有并剥离；扩展只允许命名空间化 `extensions`，每个命名空间原子合并。旧未知字段迁入 `extensions.legacy`。
- **视觉重复哈希**：排除稳定 ID、名称、时间戳、设备字段和扩展字段；包含基础皮肤与全部背景/文字/边框/发光/强度/倍率。
- **Selection**：operation-idempotent last-successful-write-wins，不返回用户可见 revision 冲突。内置 ID 作为符合语法的 opaque ID 保存；无法识别时客户端回退 `follow-theme` 并修复云端。
- **Order**：发送完整期望顺序；服务端过滤重复、无效和删除 ID，并把并发新增但遗漏的 active ID 按创建时间和 ID 追加末尾。
- **Pending selection**：旧 null 使用原子 compare-and-establish。两客户端竞争时只有第一个有效设备选择成功，失败方接受已建立选择。
- **Change cursor**：账号 palette state 维护单调 `change_seq`。增量响应包含 changes、nextCursor、hasMore、resetRequired；cursor 缺失/过期时返回 active 全量和新水位，并校验客户端提交的至多十个本地已知 ID 的 tombstone 状态。
- **Conflict-copy selection**：若当前设备正在使用的本地内容被保存为已上传冲突副本，设备选择切换到新 ID；若副本因满库仅本地待上传，云端选择保持原值。
- **Theme Plaza duplicate**：发现相同视觉内容时，确认前不写引用。选择使用已有色板时，在同一事务记录首次引用并关联已有 palette ID；选择保留新色板时创建新 ID 并记录引用。

## 7. 数据模型目标

建议 PostgreSQL 资源：

- `user_palette_account_state`：账号级容量锁、迁移状态和单调 `change_seq`。
- `user_custom_palettes`：账号、稳定 ID、当前 revision、active/deleted 状态、change sequence 和时间戳。
- `user_custom_palette_revisions`：不可变完整内容、内容哈希、来源 operation、创建时间。
- `user_palette_selection`：选择 kind/ref、独立 revision。
- `user_palette_order`：正式 ID 顺序、独立 revision。
- `user_palette_operations`：幂等请求哈希和权威响应。

表名可在设计实现中调整，但边界不得退回整库 revision。

## 8. 旧数据迁移

1. 新表 expand-only 创建。
2. 旧 JSON 每套色板保留稳定 ID、内容和有效时间戳，迁移 revision 从 1 开始。
3. 旧数组顺序成为初始正式顺序。
4. format:2 使用确定性默认值升级完整 format:3。
5. 旧 active ID 指向自定义色板时迁移为 `custom:<id>`。
6. 旧 active 为 null 时进入待建立选择；第一个新客户端用有效设备选择原子建立，之后普通缓存不能覆盖。
7. 重复 ID、非法内容、超过十套或无效 active ID 进入异常清单，不静默删改。
8. 影子对账通过后进入短暂色板写入维护，执行最终增量迁移并切换权威。

## 9. 发布与回滚

- 当前生产：Theme Plaza read=true、write=false、auto-publish=false。
- 新旧数据先影子对账，不长期双写。
- 切换期间暂停账号色板写入，读取和本地草稿保留。
- 切换后旧 GET 兼容，旧 PUT fail-closed。
- Theme Plaza 依次开放互动、保存、分享；自动发布继续关闭直到独立审核门禁通过。
- 回滚只关闭能力并回滚代码；不删除新表、版本历史或删除标记，不重新开放旧 PUT。
- 旧整库表冻结至少 30 天且跨过两个稳定生产版本。

## 10. 验收门禁

### 数据

- 账号、色板、ID、顺序和高级样式无损对账。
- 没有未经批准的数据减少；异常账号全部可枚举。
- 有效色板不超过十套。

### 并发

真实 PostgreSQL 覆盖不同色板并发、同色板自动合并、同字段冲突副本、第十套竞争、删除与旧设备、过期 base、幂等重试、选择合法性。

### Web

首页只加载必要选择/一套色板；设置页延迟加载；同一会话不重复首同步；草稿、保存、离线队列、账号隔离、未保存提示和单套分享资格全部通过单元、Smoke 和视觉验证。

### 性能与生产

首页核心指标无显著退化；API 不可用不阻塞游戏；无后台轮询；备份与恢复演练、影子对账、锁定 commits、生产 Smoke 和可执行回滚方案全部完成。
