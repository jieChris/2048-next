# 主题广场 PRD

## 文档状态

- 阶段：需求已整理，待产品确认后进入设计与实施计划。
- 产品名称：主题广场。
- MVP 实际分享对象：玩家创建的一套非内置“自定义方块色板”，不是控制全站页面外观的“界面主题”。
- 涉及仓库：`2048-next`（Web UI）、`2048-game-api`（权威 API、数据、审核与管理）、`2048-next-android`（色板格式兼容；MVP 不要求提供广场页面）。
- 当前授权：仅编写 PRD 和领域术语，不修改业务代码，不提交、不推送、不部署。

## 1. 背景与问题

玩家已经可以创建、复制、重命名、导入、导出并编辑自定义色板，但目前这些作品主要停留在自己的设备或账号色板数据中，没有公开展示、发现、评价和一键复用的闭环。

用户希望新增“主题广场”：

1. 每名登录用户最多公开分享一套自己的非内置作品；
2. 其他玩家可以公开浏览并完整预览；
3. 登录玩家可以一键保存到自己的色板仓库；
4. 登录玩家可以点赞或点踩；
5. 系统统计作品被引用的次数；
6. 作者可以为公开作品命名，但名称必须合规并经过审核；
7. 审核优先接入 DeepSeek API，以较低成本完成大部分语义审核；疑难情况由管理员处理。

这不是简单增加一个列表页。若公开作品直接引用作者正在编辑的本地对象、若“保存成功”和引用计数不是同一事务、或若 AI 失败时默认放行，都会产生内容被悄悄替换、统计失真、色板丢失或违规内容公开等问题。因此产品必须先明确快照、版本、仓库和审核的权威边界。

## 2. 当前系统基线与实施前置

### 2.1 “界面主题”与“自定义色板”已分离

- 界面主题控制页面、按钮、面板和棋盘容器的整体外观。
- 自定义色板控制方块的背景、文字、边框、发光颜色以及发光强度。
- 当前只有自定义色板可由玩家编辑；不存在玩家可自由编辑的完整全站界面主题。

因此 MVP 页面可以叫“主题广场”，但接口、数据和内部术语应使用“广场作品 / 色板发布版本”，不得把内置界面主题伪装成可分享对象。

### 2.2 色板仓库存在跨端不一致

- Web 当前以 `tile_palette_profiles_v1` 为主要本地存储，并已有完整的 2 的幂、Fibonacci、文字、边框、发光、整体发光强度和单块倍率数据。
- `2048-game-api` 已提供 `/api/me/app-palettes` 及 CAS revision，但当前 Web 尚未接入完整的账号同步流程。
- API 与 Android 当前把账号自定义色板上限定义为 8 套；Web 的本地创建/导入路径尚未统一执行该上限。
- API 当前色板 `format: 2` 保存颜色数组，但尚未包含 Web 已有的 `glowIntensity` 和 `glowMultipliers[26]`。若直接接入广场，发光强度信息会丢失。

### 2.3 上线前置条件

主题广场正式开放写操作前，必须先完成：

1. 将账号色板权威格式升级为可无损表示当前 Web 色板的 `format: 3`；
2. 新格式至少补齐 `glowIntensity: 0～100` 与 `glowMultipliers[26]: 0～200`；
3. API 必须在旧格式客户端写回时按 palette ID 合并并保留新字段；更新后的 Web、Android 也必须无损透传未知字段，不能依赖旧客户端自行理解新格式；
4. Web 接入账号色板同步、dirty 状态、revision 冲突处理和最多 8 套的统一限制；
5. 广场分享和保存只读取/写入服务端权威色板仓库，不能以孤立的浏览器 localStorage 作为引用统计依据。

若这五项未完成，广场可以只读预览，但不得开放“分享”和“一键保存”。

## 3. 产品目标

### 3.1 核心目标

- 建立从创作、分享、审核、发现、预览、评价到保存复用的完整闭环。
- 每个账号同时最多有一套公开作品，避免低质量批量铺量。
- 公开作品是经过审核的不可变快照，作者后续编辑私人色板不会影响公共内容和他人副本。
- “一键保存”成功后，作品确实进入账号色板仓库；只有这个事务成功才增加引用次数。
- 点赞、点踩、引用均可防止重复计数和并发绕过。
- DeepSeek 承担大多数低风险名称的自动审核，但服务端规则与管理员仍是最终权威。
- 任何审核、下架或修复操作只影响目标作品，不批量隐藏无关作品或用户数据。

### 3.2 成功标准

- 同一账号不可能同时公开两套广场作品。
- 内置色板不能直接分享；必须先创建自定义副本。
- 保存成功与引用事件原子提交，失败不计数，重试不重复计数。
- 同一账号对同一发布版本最多有一个评价状态和一次引用计数。
- 公开快照、作者私人源色板、保存者副本三者相互独立，任何一方删除或编辑都不悄悄改写另外两方。
- AI 超时、空响应、非法 JSON 或服务不可用时不自动公开内容。
- 公开页面不渲染任意 CSS、HTML、图片 URL 或脚本，只渲染服务端允许的结构化色值与数值。
- 当前 Web 色板中的背景、文字、边框、发光、整体强度和单块倍率可无损分享及保存。

## 4. 范围外

- 不允许玩家上传任意 CSS、字体、图片、声音、动画或页面布局。
- 不把内置界面主题或内置色板分享到广场。
- MVP 不提供评论、关注、私信、付费主题、创作者收益或主题合集。
- MVP 不提供自动推荐算法；只提供明确、可解释的排序与搜索。
- MVP 不要求 Android 提供主题广场浏览 UI，但 Android 必须无损保留账号色板新格式。
- 不使用 AI 评判色板“好不好看”，审核只处理合规与安全。
- 不支持多人共同编辑同一作品，也不提供作者更新自动推送到他人副本的订阅机制。

## 5. 角色与权限

### 5.1 游客

- 可以浏览、搜索、排序和查看作品详情。
- 不能分享、保存、点赞、点踩或举报。
- 点击受限操作时进入登录引导，不丢失当前作品位置。

### 5.2 登录玩家

- 可以分享自己账号仓库中的非内置自定义色板。
- 同时最多拥有一个广场作品；可以撤下、替换或重新提交审核。
- 可以保存他人的已发布版本、评价和举报。
- 不能评价、引用或举报自己的作品；自己的源色板已在仓库中，详情页显示“这是你的作品”。

### 5.3 管理员

- 在现有 `2048-next` 管理后台处理主题广场人工审核和举报。
- 可以批准、拒绝、隐藏、恢复单个作品版本，并必须填写结构化原因。
- 可以查看 DeepSeek 审核结果、重试状态和审计日志，但不能看到 API Key。
- MVP 不提供“一键批量隐藏”或任意 SQL 操作，防止误伤无关作品。

## 6. 核心领域规则

### 6.1 一人一套

- 产品和规则中的“一人一套”实际按账号执行：每个账号一个作品槽位；MVP 不声称能够识别不同账号是否属于同一自然人。
- 数据库对 `owner_user_id` 建立唯一约束，每个账号只有一个“广场作品槽位”。
- 一个槽位可同时指向：一个当前已发布版本，以及至多一个待审核的新版本。
- 作者首次分享时创建槽位；撤下后可以在同一槽位重新分享，不是“一生只能分享一次”。
- 已有公开版本时提交更新，旧版本继续公开，直到新版本审核通过并原子替换。

### 6.2 发布版本不可变

- 分享时从账号色板仓库读取完整色板并生成规范化快照与内容哈希。
- 内容哈希只覆盖规范化后的视觉数据：固定字段顺序、统一 HEX 大小写与透明值表示，不包含私人 palette ID、私人名称、作者或发布时间。
- 发布后不原地修改快照。改名、换色或调整发光都创建新版本并重新审核。
- 新版本发布后，其点赞、点踩与引用从零开始，防止作者用旧口碑替换成完全不同的内容。
- 旧版本已保存到其他账号的副本继续可用，不随下架、撤回或作者删号而消失。

### 6.3 保存副本

- 保存操作生成新的私人色板 ID，名称默认使用公开标题，并遵守现有 20 字符上限与重名处理规则。
- 保存只加入仓库，不自动切换当前正在使用的色板；成功后提供“立即使用”次级操作。
- 副本与发布版本断开实时关系，作者后续更新或下架不改变副本。
- 若账号仓库已满 8 套，返回明确错误并引导前往色板中心管理，绝不自动删除或覆盖现有色板。
- 若仓库中已存在相同规范化内容哈希，返回已有色板并视为幂等完成，不再创建重复副本，也不新增引用事实。

### 6.4 引用次数

- “引用次数”定义为成功保存该发布版本的去重账号数，不是按钮点击数或网络请求数。
- 同一账号删除副本再保存同一版本，可以重新获得副本，但不重复增加引用次数。
- 引用事实表示“曾成功保存”；当前是否仍有副本必须根据账号仓库中对应的色板 ID 判断，不能仅凭历史引用事实显示“已保存”。
- 保存事务失败、仓库已满、版本已下架、格式不兼容或认证失败均不增加引用次数。
- UI 显示“引用 X 次”，辅助说明为“按账号去重的成功保存次数”。

### 6.5 点赞与点踩

- 每个登录账号对每个发布版本只有一个状态：`like`、`dislike` 或 `none`。
- 再次点击当前状态会取消；从点赞切换到点踩或反向切换必须原子更新。
- 作品作者不能评价自己的版本。
- 点赞和点踩分别展示，不把点踩隐藏在净分中。

### 6.6 重复作品与再分享

- 保存自广场的副本仍是自定义色板，可以继续编辑。
- 其他用户不得把与现有公开版本内容哈希完全相同的副本再次发布；系统应返回原作品入口。
- MVP 只自动拦截完全相同的内容。近似抄袭或署名争议通过举报与管理员单项处理，不引入不可靠的“相似度自动定罪”。

## 7. 信息架构与页面展示

### 7.1 入口

- 在色板中心的外观与配色区域增加“主题广场”入口。
- 新增独立页面 `theme_plaza.html`，保留返回色板中心和回首页入口。
- 作者在自定义色板操作区看到“分享到主题广场”或“更新广场分享”；内置色板显示禁用说明“请先创建副本”。

### 7.2 广场列表

页面至少包含：

- 搜索：按公开标题和作者当前昵称搜索；
- 排序：最新发布、最多引用、最多好评；
- 筛选：全部、2 的幂预览、Fibonacci 预览不是独立作品筛选，而是预览切换；同一作品必须包含两套规则数据；
- 游标分页与加载失败重试；
- 空状态、审核中状态入口和未登录操作提示。

每张作品卡片至少展示：

- 公开标题；
- 作者当前昵称与用户页入口；
- 真实 4×4 方块预览，体现背景、文字、边框与发光；
- 点赞数、点踩数、引用次数；
- 发布时间；
- “查看详情”和“一键保存”操作；
- 当前用户已保存、自己的作品或不可保存时的明确状态。

### 7.3 作品详情

MVP 使用可直接访问和分享链接的独立详情页；详情页至少展示：

- 完整标题、作者、发布时间与版本号；
- 2 的幂 / Fibonacci 切换；
- 16 格标准方块完整预览，高阶 2 的幂颜色可展开查看；
- 背景、文字、边框、发光与强度的实际合成效果，而不是只显示 HEX 色块；
- 点赞、点踩、引用统计和当前用户状态；
- 一键保存、保存后立即使用、举报；
- 已下架或版本更新时的明确提示，不显示空白或错误快照。

### 7.4 我的分享

- 显示当前公开版本和待审核版本；
- 状态：未分享、AI 审核中、待人工审核、已发布、未通过、已下架、已撤下；
- 显示可公开的结构化原因，不直接展示模型原始推理文本；
- 支持更新分享、取消待审核版本、撤下公开版本；
- 提交更新前明确提示：新版本审核通过后会替换公开内容，且新版本统计重新开始。

## 8. 用户流程

### 8.1 首次分享

1. 玩家在色板中心选中一套自定义色板。
2. 客户端确认账号色板已完成同步且无未解决 revision 冲突。
3. 玩家点击“分享到主题广场”。
4. 输入 2～20 个字符的公开标题；公开标题与私人色板名称相互独立。
5. 前端显示完整预览和审核提示，玩家确认提交。
6. API 从该玩家的服务端色板仓库按 `palette_id` 取快照，不接受客户端任意 JSON 直接发布。
7. 确定性校验通过后创建待审核版本并返回 `202`。
8. DeepSeek 审核通过则自动发布；需要复核则进入管理员队列。

### 8.2 更新分享

1. 作者选择自己仓库中的任意自定义色板并点击“更新广场分享”。
2. 创建新的不可变候选版本；旧公开版本保持可见。
3. 候选通过审核后原子成为当前版本，旧版本退出公开列表。
4. 新版本统计从零开始；旧版本的历史数据和他人副本不删除。

### 8.3 一键保存

1. 游客点击时先引导登录；登录后返回原作品。
2. 客户端先确认本地与账号色板仓库已同步，无 dirty 冲突。
3. API 在同一数据库事务内锁定用户色板文档，验证容量和版本状态，创建私人副本并写入引用事件。
4. 成功后返回新的完整色板文档、revision、色板 ID，以及是否创建副本、是否首次引用和当前是否已保存。
5. 客户端更新本地仓库并显示“已保存”；不自动改变当前色板。

### 8.4 评价

1. 登录玩家点击点赞或点踩。
2. 前端可以乐观更新，但必须以 API 返回的用户状态和最新计数校正。
3. 网络失败时回滚，不把失败点击计入公开数字。

### 8.5 举报与下架

1. 登录玩家选择结构化举报原因，可附不超过 200 字的补充说明。
2. 同一账号对同一版本只能保留一条有效举报。
3. 举报数量不会自动隐藏作品，避免恶意围攻；管理员逐项判断。
4. 管理员隐藏后，列表和详情不再公开，但已保存副本不删除。

## 9. 名称与内容合规规则

### 9.1 确定性校验

公开标题在调用 AI 前必须通过：

- 去除首尾空白并规范化连续空白；
- 长度 2～20 个 Unicode 字符；
- 拒绝控制字符、不可见字符、换行、HTML 标签、URL、联系方式和明显广告导流；
- 拒绝现有敏感词规则命中的内容；
- 拒绝冒充“官方、系统、管理员、内置、2048 Next 官方”等保留身份的名称；
- 标题不要求全局唯一，以作者和作品 ID 区分；
- 色板数据必须符合当前权威格式、数组长度、颜色格式和强度范围。

确定性失败直接返回可理解的错误，不调用 DeepSeek，也不消耗审核成本。

### 9.2 DeepSeek 的定位

DeepSeek 是第二层语义分类器，不是唯一安全边界，也不是最终数据库权威。它用于识别简单关键词难以覆盖的变体表达、仇恨、色情、暴力、违法引导、骚扰、政治敏感、冒充和广告导流风险。

只向 DeepSeek 发送：

- 规范化后的公开标题；
- 用户界面语言；
- 审核政策版本和分类说明。

不得发送邮箱、用户 ID、IP、Token、完整账号资料或不必要的色板 JSON。结构化色值由本地规则验证，不需要交给语言模型判断。

### 9.3 AI 输出合同

服务端要求 JSON 输出并严格二次解析，例如：

```json
{
  "decision": "allow | review",
  "categories": ["impersonation"],
  "reason_code": "OK | NEEDS_MANUAL_REVIEW"
}
```

- `allow`：确定性规则已通过且模型未发现风险，自动发布；
- `review`：进入人工审核，不由模型直接执行隐藏或删除；
- 非法 JSON、空内容、未知枚举或字段缺失均视为审核失败，不得默认通过。

### 9.4 可用性与成本控制

- 审核异步执行，提交接口快速返回“审核中”；
- MVP 直接以数据库中的审核状态、重试次数和 `next_review_at` 作为持久任务队列，由 API 后台任务领取处理；不为此单独引入 Redis 或消息队列；
- 单次请求使用短系统提示、低温度、合理 `max_tokens` 和 JSON Output；
- 按“规范化标题哈希 + 审核政策版本 + 模型版本”缓存安全结果，重复内容无需重复付费；
- 空响应或暂时错误最多自动重试一次，之后进入人工审核；
- DeepSeek 故障时已发布版本保持可见，新候选保持待审核，不 fail-open；
- 记录请求哈希、模型、政策版本、延迟、Token 用量、结果和错误码，不记录 API Key 或模型长篇推理；
- 模型名、超时和预算告警由服务端环境配置，PRD 不写死会快速过期的单价。

官方 DeepSeek 文档说明 JSON Output 偶尔可能返回空内容，因此空响应重试和人工兜底是发布必要条件，不是可选优化。

## 10. 状态机

```text
未分享
  └─ 提交 → pending_ai
               ├─ allow → published
               ├─ review → manual_review
               └─ 请求失败重试后仍失败 → manual_review

manual_review
  ├─ 管理员批准 → published
  ├─ 管理员拒绝 → rejected
  └─ 作者取消 → cancelled

published
  ├─ 作者提交更新 → published + pending_ai（旧版本继续公开）
  ├─ 作者撤下 → withdrawn
  ├─ 管理员隐藏 → hidden
  └─ 账号删除/停用 → hidden
```

- 任一时刻每个作品槽位最多一个公开版本和一个候选版本。
- `rejected`、`cancelled`、`withdrawn`、`hidden` 不公开展示。
- 管理员恢复只能恢复经过审核的具体版本，不能恢复未知或已被替换的数据。

## 11. 功能需求

### 11.1 浏览（PLAZA）

- **PLAZA-01** 公开列表和详情无需登录。
- **PLAZA-02** 仅返回状态为 `published` 且作者账号可公开展示的当前版本。
- **PLAZA-03** 支持 `latest`、`most_referenced`、`most_liked` 三种稳定排序和游标分页。
- **PLAZA-04** 搜索只匹配公开标题与作者当前昵称，必须有长度限制和频率限制。
- **PLAZA-05** API 返回当前用户的 `vote`、`saved`、`owned` 状态；`saved` 只表示当前仓库仍有对应副本，不能把已删除副本的历史引用误报为“已保存”；游客返回空状态。
- **PLAZA-06** 页面在浅色/夜间、桌面/移动端均使用实际渲染规则预览，不用近似静态图片代替。

### 11.2 分享（SHARE）

- **SHARE-01** 仅登录账号可分享自己服务端仓库中的自定义色板。
- **SHARE-02** 数据库唯一约束保证每个账号一个作品槽位。
- **SHARE-03** 分享接口按 `palette_id` 从服务端仓库生成快照，拒绝内置、缺失、脏冲突或不兼容色板。
- **SHARE-04** 私人色板编辑、改名和删除不自动改变公开版本。
- **SHARE-05** 更新创建新版本并重新审核；旧版本审核期间继续公开。
- **SHARE-06** 完全相同的公开内容哈希不能被其他作者重复发布。
- **SHARE-07** 每个账号同时只能有一个待审核候选，并限制重复提交频率。

### 11.3 保存（SAVE）

- **SAVE-01** 仅登录账号可保存，不能保存自己的作品。
- **SAVE-02** 保存、账号色板 revision 更新和首次引用写入必须处于同一事务。
- **SAVE-03** 仓库满、格式错误、版本非公开或写入冲突时不增加引用。
- **SAVE-04** 相同内容已存在时返回现有色板，操作幂等；不创建副本，也不新增引用事实。
- **SAVE-05** 保存后不自动应用，避免无提示改变当前游戏外观。
- **SAVE-06** 返回的文档必须保留全部高级字段，旧端写入不得清除未知字段。

### 11.4 评价与举报（ENGAGE）

- **ENGAGE-01** 点赞/点踩互斥，重复点击取消，服务端唯一约束防重复。
- **ENGAGE-02** 作者不能评价自己的作品。
- **ENGAGE-03** 计数由服务端事实表派生，前端提交任意计数无效。
- **ENGAGE-04** 举报需登录、按账号与版本去重，不因举报数量自动下架。
- **ENGAGE-05** 作品版本替换后，新版本评价与引用重新计算。

### 11.5 审核与管理（MOD）

- **MOD-01** 确定性校验先于 DeepSeek。
- **MOD-02** AI 审核异步、失败关闭、输出严格校验。
- **MOD-03** AI 判定 `review` 或不可用时进入人工队列，不自动删除或批量隐藏。
- **MOD-04** 管理员操作必须单作品、带原因、写审计。
- **MOD-05** 管理后台展示候选完整预览、作者、名称、规则命中、AI 结果、举报和历史版本。
- **MOD-06** 已发布内容被隐藏时保留数据和他人副本；恢复需指定版本并记录原因。

## 13. 数据模型草案

### 13.1 `theme_plaza_listings`

- `id`
- `owner_user_id`，唯一
- `published_version_id`，可空
- `pending_version_id`，可空
- `created_at`、`updated_at`

### 13.2 `theme_plaza_versions`

- `id`
- `listing_id`
- `revision_no`，同作品内唯一
- `public_title`
- `palette_snapshot` JSONB
- `content_hash`
- `moderation_status`
- `moderation_reason_code`
- `policy_version`
- `model_name`
- `review_attempts`、`next_review_at`、`last_review_error`
- `submitted_at`、`published_at`、`reviewed_at`

快照只保存规范化公开数据，不保存私人 palette ID、邮箱、Token、IP 或任意 CSS。

### 13.3 `theme_plaza_votes`

- `version_id`
- `user_id`
- `value`：`-1` 或 `1`
- `updated_at`
- 唯一：`(version_id, user_id)`

取消评价删除该事实行；切换评价更新同一行。

### 13.4 `theme_plaza_references`

- `version_id`
- `user_id`
- `last_saved_palette_id`，可空；重新保存时更新，副本删除后不删除引用事实
- `first_saved_at`
- 唯一：`(version_id, user_id)`

该表记录历史首次成功引用。私人副本删除后不删除引用事实。

### 13.5 `theme_plaza_reports`

- `version_id`
- `reporter_user_id`
- `category`
- `note`
- `status`
- `created_at`、`resolved_at`、`resolved_by`
- 唯一：`(version_id, reporter_user_id)`

管理员决定继续写入现有 `audit_events`，不另建重复审计系统。

## 14. 数据一致性与并发不变量

- 每名用户最多一个 listing，由数据库唯一约束而非前端按钮保证。
- 每个 listing 最多一个 published version 和一个 pending version。
- 发布版本内容不可更新，只能新增版本并切换引用。
- 点赞/点踩、引用和举报按数据库唯一键去重。
- 保存副本时锁定账号色板文档并在同一事务中：验证容量 → 添加副本 → 增加 revision → 写引用事实 → 提交。
- 并发保存同一版本最终只产生一个引用事实；相同幂等键返回相同结果。
- 删除保存副本不删除历史引用事实；再次保存只更新 `last_saved_palette_id`，不增加引用次数。
- 发布版本在审核通过的事务中切换；读请求永远不会看到半发布状态。
- AI、管理员或客户端均不能直接提交点赞、点踩、引用的聚合数字。
- 账号停用、删除或进入待删除状态后，其作品不再公开；其他账号已保存副本保持不变。

## 15. 安全、隐私与滥用防护

- DeepSeek API Key 仅存在于 `2048-game-api` 服务端环境变量，不进入前端、日志或响应。
- 标题按纯文本转义，色板快照仅允许固定字段、固定数组长度、HEX/透明哨兵值和有限数值范围。
- 拒绝 `url()`、渐变、CSS 变量、HTML、SVG、data URL 和任意外链资源。
- 将用户标题作为 JSON 数据嵌入审核请求，系统提示明确禁止遵循标题中的指令，降低提示注入风险。
- 分享、更新、投票、保存、举报和搜索分别设置账号/IP 频率限制。
- 不允许同一账号通过多端或并发请求绕过一个作品槽位、一次评价和一次引用；多账号滥用通过频率限制和管理员处置控制，不宣称系统能识别同一自然人的所有账号。
- 管理员隐藏、恢复、批准、拒绝均必须逐项操作并审计；不因模型升级或迁移批量重分类历史作品。
- DeepSeek 原始返回只用于受限诊断；用户只看到经过映射的结构化原因。
- 隐私政策需披露公开标题会提交给第三方模型服务进行合规审核；除此之外不发送账号资料或色板内容。
- 公开 API 不返回邮箱、内部用户 ID、审核提示词、模型原始推理或举报者信息。

## 16. 性能、可用性与无障碍

- 列表接口默认每页 20 项，使用稳定游标；`limit` 有服务端上限。
- 预览由结构化色值在客户端渲染，不为每件作品生成和存储截图。
- 列表卡片只渲染一个标准 4×4 预览，详情按需加载高阶与 Fibonacci 数据。
- 点赞、点踩与引用计数来自索引化事实表；可增加短期只读缓存，但数据库事实保持权威。
- DeepSeek 审核不阻塞用户提交请求；队列可重试，服务重启不丢任务。
- 页面支持键盘操作、可见焦点、语义按钮、`aria-pressed` 评价状态和非仅颜色表达的成功/失败提示。
- 新页面及详情覆盖层必须按项目视觉规范覆盖 320×568、390×844、768×1024、1280×720 的浅色与夜间矩阵。
- 颜色可能由用户自由选择，预览需提供边界和数值标签；低对比度不作为合规拒绝原因，但可显示可读性提醒。

## 17. 管理后台需求

主题广场管理只加入现有 `2048-next` 管理后台；不改造独立的 `2048-ranked` 管理页面。

### 17.1 审核队列

- 按 AI 审核中、待人工、已拒绝、已隐藏、举报待处理筛选；
- 展示真实完整预览，而不是只看标题；
- 显示作者、提交时间、规则命中、AI 结构化结果、模型/政策版本和重试错误；
- 批准、拒绝、隐藏、恢复要求二次确认和原因；
- 所有操作只作用于当前明确版本。

### 17.2 运行健康

- DeepSeek 调用成功率、空响应率、超时率、重试数、平均 Token 和成本估算；
- 待审核数量、人工队列年龄、审核时延；
- 分享、保存、引用、评价、举报及仓库已满错误数量；
- 明确区分 AI 故障、确定性拒绝、人工待审和管理员下架。

## 18. 指标与观测

### 18.1 产品指标

- 有效公开作品数与独立作者数；
- 广场访客 → 详情查看 → 保存成功的转化；
- 每个版本的独立引用账号数；
- 点赞/点踩参与率；
- 更新分享率和撤下率；
- 仓库已满导致的保存失败率。

### 18.2 审核指标

- 自动通过比例；
- 进入人工审核比例；
- 管理员推翻 AI 建议的比例；
- 审核 P50/P95 时延；
- DeepSeek 空响应、超时、非法 JSON 和调用成本；
- 发布后被举报和最终下架的比例。

指标只用于诊断和产品改进，不自动触发批量隐藏。

## 19. 验收标准

### 19.1 分享与版本

- 登录玩家可分享一套非内置自定义色板；第二套请求转为更新现有作品，而不是创建第二个公开槽位。
- 两个并发首次分享请求最终只有一个作品槽位和一个候选版本。
- 分享后编辑或删除私人源色板，公开快照不变化。
- 更新审核期间旧版本正常浏览；审核通过后原子切换，新统计为零。
- 内置色板、缺失色板、未同步色板和完全重复内容均被明确拒绝。

### 19.2 展示

- 列表卡与详情真实体现两种规则族、四个颜色维度、整体发光和单块倍率。
- 列表显示标题、作者、时间、点赞、点踩、引用及当前用户状态。
- 四种尺寸与双主题无横向溢出、弹层遮挡或不可达操作。

### 19.3 保存与引用

- 保存成功后新副本出现在账号与本地色板仓库中，当前使用色板不自动变化。
- 仓库已有 8 套时保存失败，现有 8 套无任何变化，引用数不增加。
- 同一账号并发或重复保存同一版本只增加一次引用。
- 已保存副本删除后，页面不再显示“已保存”；再次保存可创建副本，但历史引用次数不再增加。
- 保存事务在数据库异常时完全回滚，不出现“引用已增加但副本不存在”。
- 作者下架或删除账号后，已保存副本仍能使用和导出。

### 19.4 评价与举报

- 点赞、点踩、取消和切换状态均正确；并发请求不重复计数。
- 作者无法评价自己的作品。
- 举报按账号去重，不会因数量自动隐藏作品。

### 19.5 审核

- 明显非法名称在本地规则阶段被拒绝且不调用 DeepSeek。
- 普通名称经 DeepSeek `allow` 后自动发布。
- `review`、空响应、非法 JSON、超时和服务不可用均不公开候选，而是进入人工队列。
- 管理员批准、拒绝、隐藏和恢复均只影响指定版本并写入审计。

### 19.6 兼容性

- Web 当前完整色板经账号同步 → 分享 → 他人保存 → 导出后，背景、文字、边框、发光、整体强度和 26 个单块倍率逐项一致。
- 旧格式 Web/Android 客户端读取后再写回时，API 兼容合并不得清除新字段；更新后的客户端还需通过未知字段无损写回合同。
- 主题广场关闭或回滚后，现有私人色板、公开快照和引用事实不丢失。

## 20. 测试要求

- API 单元：格式校验、一人一套、版本不可变、重复哈希、投票互斥、引用去重、举报去重。
- API 事务：并发分享、并发保存、仓库满、revision 冲突、事务回滚。
- 审核单元：确定性规则、允许、人工复核、空 JSON、非法 JSON、超时、重试和 prompt injection 文本。
- 前端单元：登录门槛、状态映射、排序/分页、乐观评价回滚、保存后不自动应用。
- 跨端合同：Web/API/Android 对 `format: 3` 的读取、写回和未知字段保留。
- 内置浏览器：分享审核中、旧版继续公开、保存、仓库满、点赞/点踩/取消、举报、管理员单项审核。
- 视觉：新页面与详情/审核覆盖层按项目规定的四尺寸、双主题基线验证。
- 发布门禁：迁移前后账号色板文档数、公开作品数、版本数、投票数、引用数只读对账；任何未批准下降阻断发布。

## 21. 发布顺序与回滚

### 21.1 发布顺序

1. 先升级账号色板格式和跨端无损写回，主题广场功能保持关闭；
2. 接入 Web 账号色板同步并验证最多 8 套、冲突和离线行为；
3. 上线数据库表与只读广场 API，后台可见但公众入口关闭；
4. 接入 DeepSeek，先以影子模式记录结果，不自动公开；
5. 人工核对样本后开启自动通过，仍保留人工兜底；
6. 开放公开浏览，再开放分享、保存、评价和举报；
7. 观察审核错误率、保存失败率和数据对账后移除临时发布开关。

不创建“内测资格”或新的用户分层；发布开关只控制功能是否全站开放。

### 21.2 回滚

- 前端入口可关闭，API 写操作可返回维护状态；
- 已发布作品可以继续只读，或在安全事件时整体暂停展示；
- 不删除私人色板、保存副本、公开快照、投票、引用或审核审计；
- 数据库迁移向前兼容，不以删除新字段作为回滚方式；
- DeepSeek 故障时只暂停新版本自动发布，不影响已有作品与他人副本。

## 22. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| “主题”与“色板”概念混淆 | UI 保留“主题广场”，数据合同明确只分享自定义方块色板 |
| Web 本地仓库与账号仓库不同步 | 写功能上线前先完成 Web 账号色板同步；脏冲突时禁止分享/保存 |
| 发光强度在现有 API 格式中丢失 | 先升级权威格式并要求旧端无损透传 |
| 作者换内容继承旧口碑 | 发布版本不可变；更新创建新版本并重置版本统计 |
| 保存成功但引用计数失败或反向 | 副本写入与引用事件同一数据库事务 |
| AI 错判或服务不可用 | 规则前置、AI 只自动通过、疑难人工、失败关闭、可重试 |
| Prompt injection | 标题作为数据传入、短固定系统提示、严格 JSON 校验 |
| 点赞/引用刷量 | 登录门槛、唯一约束、账号/IP 频率限制、自评禁止 |
| 恶意举报导致误下架 | 举报不自动隐藏，管理员逐项处理 |
| 管理操作误伤大量正常作品 | 不提供批量隐藏，操作必须指定版本、原因和审计 |
| 完全复制他人作品再发布 | 规范化内容哈希去重；近似争议走举报，不自动定罪 |

## 23. 已确定的产品决策

- 页面名使用“主题广场”，MVP 对象为自定义方块色板。
- 游客可浏览；分享、保存、评价和举报必须登录。
- 每个账号最多一个公开作品槽位，不限制终身分享次数。
- 分享和更新均使用不可变快照并审核；私人编辑不自动同步到广场。
- 更新通过后按新发布版本重新统计互动。
- 引用次数按发布版本和账号去重，只在副本真正保存成功后增加。
- 保存产生独立副本，不自动应用，也不跟随作者更新。
- DeepSeek 负责低风险语义自动通过；疑难和失败进入人工，不让模型直接批量隐藏内容。
- 管理功能进入 `2048-next` 现有后台，不修改 `2048-ranked` 后台。
