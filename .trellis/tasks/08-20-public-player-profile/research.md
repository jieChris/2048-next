# 开源个人主页参考

| 项目 | 可借鉴部分 | 适配结论 |
| --- | --- | --- |
| Tabler | 封面、头像、资料摘要、统计卡片、时间线和编辑弹窗 | MIT；最适合作为可实现的视觉骨架 |
| Lichess | 玩家身份、成绩、对局记录的主次层级 | 产品结构契合；AGPL，仅借鉴信息架构 |
| osu-web | 玩家主页的成绩、勋章和活跃记录组织 | 功能成熟但技术栈过重；AGPL，仅借鉴信息架构 |
| Bento | 个性化卡片拼贴和强视觉重点 | 适合作为风格选项，不适合直接充当完整玩家资料系统 |
| LinkStack | 头像、简介、主题定制 | 偏链接主页，无法承载本项目的成绩与回放主线 |

建议基线：Tabler 的稳定资料结构 + Lichess 的玩家数据层级 + 少量 Bento 卡片感，直接沿用项目现有技术栈实现。

## 头像存储与审核现状

- 账号表已有 `avatar_url`，但用户自助接口当前只允许修改昵称，头像 URL 仅管理员可写。
- 项目已有腾讯 COS 回放对象存储和签名能力，但当前对象写入函数面向文本回放，不是通用图片上传链路。
- 成就图标上传上限为 256 KB，直接以 data URL 存入数据库；头像数量会随用户增长，不能复用这种数据库存储方式。
- 规划阶段曾建议独立 COS 媒体桶；核对当前自托管部署后，首版采用独立私有持久卷和待审记录：私有暂存、人工批准后经 API 公开，账号表只保留已批准头像引用。存储模块保持独立，未来多实例时可换成 COS。
- 首版采用人工预审；若待审量实际超过运营能力，再接入自动图像审核作为前置筛查，人工处理命中项。

## 成就系统复用结论

- 后端已有三张权威表：`achievement_definitions`、`user_achievements`、`user_achievement_showcase`；展示表以 `slot BETWEEN 1 AND 3` 保证三个固定槽位。
- 现有公开接口 `GET /api/user/:id/achievements` 已能返回指定玩家获得的真实成就定义与获得时间，但当前没有返回勋章墙槽位。
- 现有 `GET /api/user/me/achievement-showcase` 只能读取当前登录用户，不适合访客查看他人主页；也不应把它改成可读取任意用户的鉴权接口。
- 最小且向后兼容的补足方式是在公开玩家成就列表项上增加可选 `showcase_slot`，避免新增接口、额外请求或第二份选择状态。
- 页面渲染必须复用 `src/services/achievement-families.ts` 与 `src/services/achievement-icons.ts`。这同时保证系列最高已得等级、特殊成就图标、国际化名称和勋章墙显示规则与游戏成就页一致。
- 原型中的“大数建筑师”“稳健长局”“竞速之星”等名称不是项目成就，已确定必须移除；原型示例改用真实成就 ID 与名称。
