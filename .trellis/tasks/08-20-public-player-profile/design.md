# 公开玩家个人主页技术设计

## 仓库边界

- `2048-game-api`：公开资料、头像审核状态、成就展示槽位、记录筛选和管理员审核的唯一权威来源。
- `2048-next`：渲染主页、编辑弹窗、头像上传、记录筛选和管理员审核交互；不保存第二份服务器状态。
- 本任务不修改 `2048-ranked`。

## 数据模型

在 `users` 增加：

- `profile_bio`：公开简介，去首尾空白后最多 80 字。
- `profile_cover`：仅允许 `tide`、`sunset`、`midnight`、`forest`、`plum`。
- `featured_mode_keys`：最多 3 个现有模式 key，顺序即主页展示顺序。

新增 `user_avatar_submissions`：

- 一名用户最多一条 `pending`，最多一条 `approved`。
- 状态只允许 `pending`、`approved`、`rejected`、`superseded`。
- 数据库只保存对象相对路径、尺寸、MIME、审核人和时间，不保存图片二进制或 base64。

## 头像存储与审核

- 原始上传最大 200 KiB，只接受 JPEG、PNG、WebP。
- 服务端按真实解码格式校验，拒绝伪扩展名、动画和异常像素尺寸。
- 服务端旋转纠正、居中裁切为 256×256、移除元数据并重新编码为 WebP；只保存处理后的副本。
- 待审文件写入独立私有目录 `USER_MEDIA_STORAGE_ROOT/pending`；通过后原子移动到 `approved`。
- 访客只能通过带用户 ID 和 submission ID 的公开头像 API 读取 `approved` 文件；待审文件只有管理员 API 可读取。
- 新头像通过前继续使用旧头像；新头像通过后旧文件标记 `superseded` 并删除。
- 首版人工预审。管理员在现有 `admin.html` 用户管理页查看、通过或拒绝。

## API

- `GET /api/user/:id`
  - 追加 `avatar_url`、`profile_bio`、`profile_cover`、`featured_mode_keys`。
- `PATCH /api/user/me/profile`
  - 更新简介、封面和代表模式；不允许直接写 `avatar_url`。
- `GET /api/user/me/avatar-submission`
  - 返回当前待审状态或最近一次处理结果。
- `POST /api/user/me/avatar-submission`
  - `multipart/form-data`，字段名 `avatar`。
- `GET /api/user/:id/avatar/:submissionId`
  - 只返回该用户已通过的不可变 WebP。
- `GET /api/admin/avatar-submissions?status=pending`
- `GET /api/admin/avatar-submissions/:id/image`
- `POST /api/admin/avatar-submissions/:id/review`
  - 请求 `{ decision: "approved" | "rejected", note?: string }`。
- `GET /api/user/:id/achievements`
  - 每条已获得成就追加 `showcase_slot: 1 | 2 | 3 | null`。
- `GET /api/user/:id/records`
  - 追加 `mode_family`、`undo` 和现有 `mode_key` 精确筛选。

## 前端页面

- 保留现有 `user.html` URL、记录删除/恢复/回放行为和全部旧 DOM ID 契约。
- 固定标签顺序：概览、模式成绩、游戏记录、成就；默认概览。
- 公开访客只能查看；本人显示“编辑主页”。
- 概览展示服务器返回的代表模式、最近三条记录和勋章墙三个槽位。
- 成就标签只展示真实已获得成就，并复用 `achievement-families.ts` 和 `achievement-icons.ts`。
- 游戏记录默认“全部模式”，分类、具体模式、撤回和排序相互独立；本人额外看到有效/已删除/全部。
- 编辑弹窗只编辑简介、五个封面和最多三个代表模式；头像单独上传进入待审。
- 页面外层使用连续的全视口画布，不再保留居中卡片外框；封面背景可在精细指针设备上做不超过 6px 的分层跟随，资料文字与头像固定，触摸设备和减少动态效果设置下停用。

## 失败边界

- 资料更新失败时保留页面旧值并显示错误。
- 头像处理、存储或数据库写入任一步失败均不得改变公开头像。
- 审核通过必须在同一数据库事务中完成旧头像失效、新头像生效和审计记录；文件移动失败时不进入事务。
- 成就、记录或头像接口单独失败时只降级对应卡片，不能阻止记录页面和导航使用。

## 分层夜景横幅 V2

- 最终桌面画布固定为 2172×272；左侧 38% 保留低对比度资料区，主要建筑集中在右侧。
- 远景层：完整不透明天空与雾光，不含建筑、栏杆或人物。
- 城市层：同一视角下的完整建筑群，真实透明背景；任何一栋建筑不得被画布或横向遮罩截断。
- 近景层：露台栏杆、灯具、植物和地面反光，真实透明背景；不重复城市建筑。
- 三层共享同一地平线、透视、蓝紫霓虹画风和光源方向，并预留至少 48px 横向运动余量。
- 禁止人物、数字、文字、徽标、伪棋盘格和半透明整片底色。
- 接入前必须分别验证尺寸与 Alpha，再将三层静态叠合检查为完整场景；任一透明层失败则停止，不进入页面。

## 昼夜横幅变体

- 昼夜必须是同一场景：共用同一套天空、城市和前景几何层，只切换各层的亮度、色温、饱和度与光效；不得为夜间另行生成或替换建筑、栏杆和植物。
- 三张几何模板统一为 2172×272；天空不透明，城市与前景必须是生成器直接输出的真实 Alpha。后处理只允许整体画布裁切、缩放和定位，禁止从完整场景制作语义遮罩。
- 城市模板只能包含完整建筑，前景模板只能包含低矮栏杆与植物；透明层不得携带天空色块、半透明矩形、棋盘格或边缘重影。
- 昼间使用低饱和灰青天空、灰蓝建筑、鼠尾草绿植物和暖白日光；夜间由 CSS 对同一层做冷蓝降亮、对比度与分层光效调整，以保证场景轮廓像素级一致。

## 验证

- API：迁移、资料白名单与长度、头像真实格式/尺寸、审核状态、公开头像隔离、成就槽位顺序、记录分类 SQL。
- 前端：本人/访客、四标签、默认全部模式、三个展示槽位与成就页一致、编辑与上传错误状态。
- 内置浏览器：320×568、390×844、768×1024、1280×720，浅色与夜间；不允许横向溢出。
