# 隐藏昵称与虚拟公开身份

## 目标

允许登录用户在个人设置中隐藏公开身份。启用后，除用户本人和具备管理权限的服务端操作外，任何公开页面、接口、链接、排行榜、历史记录与回放都不得泄露真实昵称或真实用户 ID，而是显示后端签发的虚拟昵称与虚拟 ID。

虚拟昵称从可扩展的昵称库中选择，首批来源为：

- 《英雄联盟》的野怪、小兵名称；
- 《天天酷跑》的角色名称；
- 后续可继续追加候选词条。

## 已确认事实

- `2048-game-api` 是账号、排行榜、记录、回放和公开身份的唯一权威后端；前端不得自行生成可信虚拟身份。
- 当前 `GET /api/leaderboard`、`GET /api/user/:id`、`GET /api/user/:id/records` 等公开接口直接返回真实 `user_id` 和昵称。
- 当前前端排行榜通过 `user.html?id=<真实数字ID>&nickname=<真实昵称>` 跳转，两个字段都会泄露。
- 当前回放 v1 水印包含真实 `owner_user_id` 与 `owner_nickname`；只改页面显示仍可从回放内容恢复真实身份。
- 回放内的身份水印不得以明文、Base64 或前端可独立还原的简单混淆形式保存；昵称、用户 ID 等身份字段必须放入仅服务端能够验证/解开的不透明载荷。
- 后端现有回放校验模块已经具备 RPL1 解码、扩展记录读取和重新编码能力，可以在服务端验证身份水印，并保证公开读取内容不暴露明文身份。
- 当前数据库没有公开身份隐藏开关、虚拟 ID 或虚拟昵称字段。
- 内部记录归属、鉴权、排位会话、排行榜聚合和管理操作仍必须使用真实用户 ID，不能把数据库外键替换成虚拟 ID。
- 当前真实账号主键和游戏数据外键为数字类型；虚拟 ID 不应写入这些数字字段，而应使用独立的文本字段或身份映射表。
- 当前版本仍处于内测；正式上线时，既有数据只作为带“内测数据”标记的记录保留，不载入正式排行榜。

## 初步要求

- 个人设置页提供“隐藏公开身份”开关，并明确说明影响范围。
- 开关状态由后端持久化，客户端只展示和提交设置。
- 一次连续隐藏期间，虚拟昵称和虚拟 ID 保持固定。
- 每次从“公开”切换为“隐藏”时，都必须随机生成一套从未用于该用户当前隐藏期的新虚拟昵称和虚拟 ID；关闭后再次隐藏不得沿用上一套身份。
- 新隐藏身份生成后，用户所有既有排行榜条目和公开历史记录都动态映射到这套当前身份，不保留旧隐藏期的公开映射；公开回放页面是例外，隐藏期间不显示任何昵称。
- 上一隐藏期的虚拟 ID 立即失效且不得重定向到新身份或真实身份，避免通过旧链接关联用户。
- 隐藏与公开的任意一次状态切换都会启动滚动 7 天冷却；冷却期间不得再次切换，接口返回下一次可切换时间，前端禁用开关并显示剩余时间。
- 对外响应统一经过同一身份投影：公开时返回真实昵称/公开 ID，隐藏时返回虚拟昵称/虚拟 ID。
- 启用后立即覆盖既有排行榜、既有历史记录、用户主页链接和公开回放，不只影响新记录；回放页面识别到隐藏状态后，真实昵称和虚拟昵称都不显示。
- 用户本人查看自己的账号设置、私有资料和记录管理时仍可看到真实昵称及内部账号信息。
- 管理接口仍可按真实用户定位，但普通公开查询不得通过真实 ID、昵称、URL 参数或回放载荷旁路恢复身份。
- 隐藏期间，普通访问者使用真实数字 ID 或真实昵称查询用户、记录或主页时统一返回不存在，不重定向到虚拟身份，避免暴露两者映射。
- 当前有效虚拟 ID 是隐藏期间唯一公开查询入口；用户本人通过鉴权接口、管理员通过管理接口仍可访问真实身份。
- 虚拟昵称库是后端静态数据或现有简单数据模块，不新增管理后台；后续通过追加词条扩展。
- 同时处于隐藏状态的用户，其虚拟昵称必须全局唯一；昵称被占用期间不能分配给其他隐藏用户。
- 当库中没有可用昵称时，后端拒绝开启隐藏并返回明确的“虚拟昵称暂时不足”错误；前端提示稍后再试，不添加数字后缀、不复用已占用昵称。
- 虚拟 ID 使用 `V-` 加不可推导的随机字母数字串，例如 `V-7K3M9Q2DXA`；不得包含或编码真实用户 ID。
- 虚拟 ID 必须由后端生成并持久化为独立的 `TEXT UNIQUE` 数据，不改变 `users.id`、`records.user_id` 等现有数字主键/外键。
- 数据库保留已签发过的虚拟 ID，保证旧 ID 不会再次分配；只有当前有效虚拟 ID 可以解析到公开身份。
- 用户恢复公开后，当前虚拟昵称立即释放，可分配给其他隐藏用户；虚拟 ID 仍永久保留为已使用且保持失效。
- 用户以后再次隐藏时，不得重新分配该用户历史上使用过的虚拟昵称，即使该昵称当前空闲。
- 关闭隐藏后恢复公开真实身份，但不得破坏既有记录归属和排行榜数据。
- 正式版本的公开排行榜只载入正式数据；内测记录即使保留，也不得因身份投影或数据迁移重新进入正式排行榜。
- 回放身份水印只能由服务端验证/解开，前端不得持有能够还原真实水印的密钥；公开身份用户的回放页面可显示服务端返回的昵称和开局时间，隐藏身份用户只显示允许公开的非身份数据，不显示任何昵称。
- 隐藏用户的回放页面同时移除虚拟 ID、用户主页入口及其他可跳转到其虚拟公开身份的链接，只显示“身份已隐藏”。
- 回放可以离线播放游戏内容，但离线状态下不解析、不显示身份水印；身份展示必须联网请求后端验证。

## 验收标准（待产品决策补全）

- 隐藏用户在排行榜中只出现虚拟昵称和虚拟 ID。
- 同一隐藏期内各公开页面使用同一套虚拟身份；经过一次“取消隐藏 → 再次隐藏”后使用全新的虚拟身份。
- 第二次隐藏后，第一次隐藏期间及更早的公开成绩全部显示第二次生成的身份，既有公开回放均不显示任何昵称，旧虚拟主页返回不存在。
- 虚拟 ID 全局唯一、大小写规范化，无法从其内容推导真实数字 ID。
- 任意切换后的 7 天内再次操作会被后端拒绝，绕过前端直接调用接口也不能成功。
- 并发开启隐藏时也不能分配相同昵称；数据库约束或等价事务边界必须保证唯一性。
- 昵称库耗尽时，用户保持公开状态且不进入冷却期。
- 用户恢复公开后，原虚拟昵称可以服务其他用户；新持有者必须获得全新的虚拟 ID，旧链接不得解析到新持有者。
- 使用隐藏用户的真实 ID 或真实昵称访问公开资料时，不返回可识别的真实身份。
- 真实 ID 查询与不存在用户使用等价的公开错误响应，不通过状态码、错误文案或重定向泄露其已开启隐藏。
- 虚拟主页、公开记录列表和公开回放保持可用；虚拟主页与记录列表使用当前虚拟身份，回放页面不显示任何昵称。
- 回放页面及下载内容不包含真实昵称或真实用户 ID。
- 隐藏用户的回放接口将昵称与公开 ID 返回为空，页面不显示真实昵称、虚拟昵称、虚拟 ID或用户主页入口。
- 直接解压、Base64 解码或阅读公开回放文件，不能得到真实昵称、真实用户 ID或其他可反查真实身份的字段；篡改身份水印必须能够被服务端识别。
- 隐藏后再次请求既有云端回放时，公开内容不含可读的真实昵称、虚拟昵称或真实用户 ID；后端仍能通过不透明水印验证真实归属并用于审计。
- 用户本人登录后仍能管理自己的真实账号和全部记录。
- 管理端仍能审计真实归属。
- 正式上线后，现有记录继续显示“内测数据”标记且不会出现在正式排行榜。
- 开关切换、排行榜、公开资料、记录列表、回放和直接真实 ID 探测均有后端测试；前端有设置与跳转 Smoke。

## 暂不纳入

- 虚拟昵称在线管理后台。
- 用户自行编辑虚拟昵称。
- 隐藏成绩或从排行榜移除；本功能只隐藏身份。
- 改写数据库中记录、排位会话等真实外键。
- 为已流出的内测回放提供远程追回或兼容迁移；正式数据从新的水印规则开始产生。
