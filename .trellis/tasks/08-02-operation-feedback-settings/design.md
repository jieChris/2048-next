# 操作反馈设计

## 范围

操作反馈仅出现在桌面完整游戏页，默认关闭。设置弹窗只保留总开关；位置编辑全部由页面浮层自身的锁控制。移动端、历史记录、排行榜、玩家主页、回放文件和服务端均不保存或展示本功能数据。

## 浮层与位置编辑

- 浮层是 `body` 下的 `fixed` 层，键帽栈是唯一定位主体。
- 锁、编辑背景和“贴近计时器／屏幕右侧／恢复默认”工具栏均绝对定位，不参与主体宽高和定位计算。
- 锁定时鼠标移入主体显示顶部锁；点击解锁后显示编辑背景和位置工具，整体非按钮区域可拖动；再次点击锁保存位置。
- 锁定和解锁必须使用相同的主体宽高、`left/top` 与键帽栈内部坐标。状态切换不得通过增删 `padding`、边框宽度或占位元素改变主体位置。
- “屏幕右侧”以键帽栈右边缘为锚点，工具栏翻到键帽左侧；“贴近计时器”以真实计时器边界为锚点。
- 自定义位置、预设位置、开关和锁定状态写入 `settings_operation_feedback_v1`。

## 键帽视觉

经典与雾青灰使用同一套几何和动效，只替换颜色：

- 普通键帽 `58 × 58px`，圆角 `17px`；退格键 `96 × 58px`。
- 字母采用约 `780` 的粗体、`28px` 字号。
- 方向箭头使用自绘圆角 SVG，不使用系统 Unicode 箭头；实际尺寸下保持与粗体字母相同的视觉密度，基准笔画约 `4.8px`。
- 退格使用自绘饱满实心轮廓，内部叉号从主体中切出，不使用字体退格符号。
- 经典主题使用暖黑灰键帽与米白字符；雾青灰主题使用冷蓝灰键帽与雾白字符。
- 无效输入使用克制的暗红渐变，字符保持高对比；不增加霓虹、切角、金属描边或额外装饰。
- 尊重 `prefers-reduced-motion`，关闭位移动画但保留状态颜色与内容更新。

## 八键上推动效

- 最多显示最近 8 个实际记录的输入，最新输入始终位于底部。
- 新键从底部以轻微上移和缩放进入；已有键稳定向上移动一个槽位；最旧键在顶部淡出后移除。
- DOM 节点使用稳定输入 ID 复用，不允许每次 `replaceChildren()` 重建全部键帽。
- 已有键位移和透明度过渡约 `240ms`；新键进入约 `280ms`，采用快速缓出并允许轻微回弹。
- 连续快速输入时，动画从当前视觉位置重新定向，不排队、不闪回、不瞬间替换。
- 年龄透明度从新到旧依次为 `1 / .80 / .64 / .50 / .38 / .29 / .21 / .14`。
- 锁定状态 5 秒没有新的可展示输入后，键帽栈整体在约 `400ms` 内渐隐；下一次可展示输入立即唤醒。解锁编辑期间始终显示八键摆位预览。

## 输入结果数据流

原始 `keydown` 只产生输入尝试元数据，不直接创建键帽或修改统计：

1. 输入管理器记录物理键标签、方向、是否长按重复以及唯一输入 ID。
2. 输入元数据与方向一起进入现有移动节流链路；被后续输入覆盖、没有真正执行的尝试不产生反馈。
3. 游戏引擎执行移动或撤回，并返回该次尝试是否实际改变盘面。
4. 操作反馈只消费引擎确认后的结果，生成键帽并更新当前局统计。

普通方向移动以 `processMoveTraversals()` 的真实 `moved` 结果为准。撤回／重做只有在恢复管线实际执行时才算有效；仅识别到撤回方向但没有可恢复状态时属于无效输入。八方向模式中 `Z` 是斜向移动，只有退格键表示撤回。

移动节流保存“方向＋输入元数据”这一整体。节流覆盖的输入不显示、不计数，避免长按时把未执行的原始键盘重复当作游戏操作。

终局边界以输入开始执行时的状态为准：导致终局的最后一次有效输入仍正常发布；对局已经终止后开始的方向、撤回或重做输入不发布、不显示、不计数。终局后的撤回仍执行既有救阵逻辑，但该次撤回本身不计数；盘面恢复为可继续状态后，后续新输入恢复正常发布与统计。

## 有效、无效与长按规则

- 单次有效输入：使用当前主题的正常键帽，计入有效输入数。
- 单次无效输入：使用红色键帽，计入无效输入数。
- 长按产生且实际改变盘面的输入：每次正常显示并计入有效输入数。
- 长按产生但没有改变盘面的输入：不显示，也不计入无效输入数。
- 成功撤回继续计入现有撤回次数；失败撤回的非重复输入显示红色并计入无效输入数。
- 键帽附近不显示任何数字。

## 统计汇总

统计汇总面板新增“有效输入数”和“无效输入数”两行，保留现有总操作数、有效移动数和撤回次数，不改变已有字段语义。两个新计数只属于当前局运行态，不上传服务端，不写入排行榜、历史记录或回放。

## 验收与测试

- 单元测试覆盖单次有效／无效、长按有效／无效、节流覆盖、八方向 `Z`、退格撤回成功／失败以及统计更新。
- DOM 测试确认容量为 8、节点身份稳定、普通键与宽退格样式正确、无效状态使用红色类。
- 布局测试在锁定前后比较主体和键帽栈的 `left/top/width/height`，要求完全一致。
- 内置浏览器在经典与雾青灰、1280×720 下验证八键上推、顶部淡出、5 秒渐隐、锁定无位移和右侧锚点。
- 测试只使用 Codex 内置浏览器，不调用或占用用户 Chrome。
