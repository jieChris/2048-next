# 持久登录与成绩投递实施计划

## 实施前门禁

1. 从确认的生产基线分别建立前端和后端修复分支；不得从带有无关调色板、排行榜样式或后端规范未提交修改的工作树直接发布。
2. 明确记录迁移前数据库备份位置、记录数/玩家数/排行榜 Top N 快照和当前 API/前端版本。
3. 先运行目标现状测试，确认本任务的红灯来自已记录缺陷，而不是把用户已有修改当成回归。
4. 在提交/推送前重新阅读前端 `smoke-testing.md`，按至少一次提交和状态可见性规则编写断言。

## Phase 1：后端认证恢复

- 在 `2048-game-api` 增加设备会话表、token 哈希和撤销索引；保留 `auth_version` 与账号删除语义。
- 扩展现有 `/api/auth/refresh` 为 cookie-first；登录、注册、密码变更和退出接口设置/撤销独立设备 Cookie。
- 返回稳定的 `TOKEN_EXPIRED`、`SESSION_REVOKED`、`ACCOUNT_INACTIVE`、`ACCOUNT_DELETED`、`AUTH_STATE_UNAVAILABLE` 机器码。
- 为旧有效 Bearer 增加一次性兑换路径；确认过期 Bearer 不会阻止有效 Cookie 恢复。
- 添加后端单元/集成覆盖：稳定 Cookie 续期、并发恢复、退出当前设备、退出全部设备、密码变更和账号删除。

## Phase 2：前端认证客户端

- 在 API 共享层维护内存访问令牌、过期时间和合并中的恢复 Promise。
- 启动时 cookie-first 恢复；对明确过期的原请求最多重试一次。
- 将自然语言 token 判断改为 HTTP 状态/稳定机器码判断。
- 保留本地历史和上传队列，不让 `clearAuth` 清理记录；主动退出只清会话。
- 兼容迁移旧 localStorage token；验证刷新、重启、断网、503 和账号切换。

## Phase 3：IndexedDB 发件箱

- 将 `local_history_store.js` 的数据库版本前移一个版本，增加同步字段和幂等升级迁移。
- 迁移旧 localStorage pending payload 到 IndexedDB；队列改为记录 ID 引用，移除 20 条静默截断行为。
- 终局钩子调整为“构建 → put → get 校验 → 清理活动态 → 上传”。
- 统一 `pending/uploading/waiting_auth/retry_wait/needs_action/invalid/synced` 状态转换和退避元数据。
- 在启动、恢复会话、联网、历史页打开和手动点击时触发扫描。

## Phase 4：历史页手动补传

- 在现有历史列表复用记录详情组件，增加同步状态徽标、错误摘要、最后尝试时间和“上传/检查并补传”按钮。
- 按 owner 规则隔离游客与账号记录；账号切换不自动越权。
- 成功显示服务器记录 ID/历史入口；失败显示可执行的下一步，不泄露 token 或完整回放。
- 对本地损坏记录提供导出/删除确认，而不是静默丢失。

## Phase 5：服务端幂等和资格兼容

- 调整 `/api/records` 的重复检测与排行榜会话关联顺序，保证普通记录可在同一记录内补齐会话信息。
- 复用既有唯一索引，补充冲突响应和稳定错误码。
- 将旧资格字段视为 `unknown`/兼容可见，不再执行整条记录批量隐藏；目标级资格仅影响对应指标。
- 对历史资格迁移先 dry-run，比较公开记录、玩家、Top N 和目标数量；未批准下降自动停止。

## Phase 6：5×5 分块上传

- 服务端实现创建任务、块幂等写入、任务状态查询和 complete 原子验算。
- 前端根据字节阈值选择普通或分块路径，保存任务 ID、已确认块索引和整体哈希。
- 断网/刷新后从任务状态继续；任何哈希不匹配进入 `needs_action`，保留原回放。
- 先在隔离环境使用超限 fixture 验证，再开放生产阈值；小记录路径必须保持不变。

## Phase 7：管理员最小运维补充

- 复用现有仪表盘/数据工具，增加“服务器已观测投递”摘要；不新建顶级上传中心，也不推断浏览器未发送记录。
- 在用户详情接入设备会话列表、撤销单个会话和撤销全部会话；操作原因与审计必填，原始凭证不可见。
- 扩展现有记录列表/详情，显示 `client_record_id`、回放指纹、验证版本、稳定错误码、幂等/升级结果、分块状态和目标级资格。
- 扩展审计事件，覆盖设备会话撤销、自助补传、幂等命中、分块完成、管理员补录和资格变更。
- 在现有数据工具或发布脚本增加固定只读对账报告；出现未批准的记录/玩家/Top N/目标榜单下降时阻断发布。
- 保留现有人工补录和单条隐藏/恢复作为最后手段；隐藏与上传、回放验证、目标资格完全分离，不增加批量隐藏或任意 JSON 直入排行榜。
- `2048-ranked` 保持零产品代码改动。

## Phase 8：最小专项验证

### 前端

- 认证恢复/错误分类单元测试；IndexedDB v2→v3 迁移测试；终局先落盘测试；手动补传状态测试。
- 相关 Smoke：登录恢复、终局刷新、断网后重试、账号切换隔离、历史页按钮和至少一次幂等请求。
- Admin 目标测试：服务器观测口径、设备会话撤销、记录诊断字段、隐藏操作隔离和只读对账阻断。
- `npm run audit:service-boundary`、目标单元测试、相关 Smoke、`git diff --check`、`npm run verify:prepush`（若被无关既有改动阻断，记录具体偏差，不擅自修改无关文件）。

### 后端

- 认证会话、Cookie 续期、撤销和旧 token 兑换测试。
- `/api/records` 的重复/冲突/会话升级/目标资格隔离测试。
- 分块任务的块重试、断点恢复、整体哈希、RPL1 验算和原子入库测试。
- Admin API 的权限、字段脱敏、单设备/全设备撤销、投递聚合、固定只读对账和审计测试。
- TypeScript、API 单元/集成测试、迁移 dry-run 与回滚演练。

### 浏览器约束

- 人工页面检查只使用 Codex/ChatGPT 内置浏览器；优先复用当前页面标签。
- 自动化使用项目既有隔离测试环境，不连接用户浏览器或生产写入。
- 本任务主要是状态/数据流改动，不新增视觉基线；若历史页新增可见组件，按 `visual-validation.md` 登记受影响矩阵后再验证。

## 风险文件与回退点

| 阶段 | 风险位置 | 回退点 |
| --- | --- | --- |
| 认证 | `src/server/auth.ts`、认证路由、前端 API helper | 关闭 cookie-first，保留旧 Bearer 兼容；设备会话表不删除 |
| 本地存储 | `js/local_history_store.js`、终局提交 runtime | 停止迁移写入，继续读取新字段；不清理旧 IDB |
| 提交 | `js/online_leaderboard_runtime.js`、`/api/records` | 恢复旧普通接口，但保留本地 `pending` 和幂等键 |
| 历史 UI | 历史页脚本/CSS | 隐藏新按钮不影响后台队列；不删除记录 |
| 分块 | 新 upload task 路由和阈值开关 | 关闭分块入口，超大记录留在 `needs_action` |
| 资格 | leaderboard 查询/迁移 | 立即恢复兼容可见查询；不执行反向隐藏 |
| 管理后台 | 现有 Admin 仪表盘、用户、记录、审计和数据工具 | 独立隐藏新增卡片/字段；核心认证与投递不依赖管理页面 |

## 发布顺序

1. 数据库加表/索引（只加不删）与后端兼容接口。
2. 后端小流量/内部账号验证设备会话和普通记录幂等。
3. 前端发布本地发件箱、恢复登录和手动补传。
4. 发布现有 `2048-next` 管理后台的最小运维字段和只读对账；不修改 `2048-ranked`。
5. 观察至少一次投递成功率、认证恢复率、pending 数量和榜单快照。
6. 单独启用大回放分块；确认小回放延迟和错误率不回归后再扩大。
7. 完成发布后再清理旧 localStorage pending 兼容代码（需另立变更）。

## 完成定义

- 所有 PRD 验收项 1–28 有可执行证据。
- 迁移前后正常记录/玩家/排行榜可见性无未批准下降。
- 没有因认证失效、网络错误、刷新或请求体过大丢失本地终局证据。
- 管理员能够诊断服务器已观测投递和撤销设备会话，但不能看到原始凭证、误判本地未发送记录或批量隐藏成绩。
- `2048-ranked` 产品代码保持零改动。
- 代码、测试、迁移和执行记录在对应仓库独立提交；未经用户明确要求不推送、不部署。
