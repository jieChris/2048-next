# 推广视频重剪执行计划

## 执行前提

- 用户复核并批准 `prd.md` 与 `design.md` 后才开始修改宣传素材或 CapCut 工程。
- 第一版素材、成片和 CapCut 草稿 `0730` 保持不变。
- 新版使用独立输出目录和 CapCut 草稿副本。
- 不修改网站正式产品逻辑；宣传专用盘面、API 数据、输入历史和转场遮罩仅用于录制与剪辑。

## 执行效率与验收纪律（强制）

本节优先级高于下方各阶段中可能导致重复验证的旧表述。目标是把时间用于已确认内容的制作，避免对错误或未批准的中间版本进行深度加工和重复审核。

### 1. 先冻结需求，再制作

- 每类素材在制作前必须写明：基准文件、允许改变的属性、禁止改变的属性和验收截图。
- 用户尚未确认字形、构图、裁切、字幕或动画方案时，只允许制作一张低成本静态设计预览；不得录制整段视频、转码、绑定 CapCut 或进行全片审计。
- 用户确认某个既有素材后，将其文件路径写为锁定基准；后续脚本不得把它纳入批量替换。
- 出现歧义时立即暂停该项并提问，禁止用“统一处理”自行扩大修改范围。

### 2. 单向阶段门禁

严格按以下顺序推进，禁止跨阶段返工式执行：

1. 文字需求清单确认。
2. 每类视觉只提交一张代表性预览确认。
3. 一次性批量生成已确认素材。
4. 一次性绑定到新的隔离草稿。
5. 一次结构检查和一次 CapCut 实机检查。
6. 用户明确授权后才允许导出。

前一阶段未通过时，不得提前执行后一阶段。

### 3. 审核必须有触发条件

- 每次审核必须提前写明：检查对象、失败条件，以及失败后会阻止哪一步；不能回答这三项的审核不执行。
- 同一输入未变化时复用上一次证据，禁止重复截图、重复联系表、重复 `ffprobe` 或重复 JSON 哈希。
- 只有相关输入发生变化或上一次检查失败，才允许重跑该检查。
- 不检查 CapCut 首页、无关时间点或未绑定素材；实机检查必须直接跳到目标镜头和目标帧。
- 中间素材只做阻断性检查；完整质量审核只在全部素材绑定后执行一次。
- 对同一 GUI 状态最多保留 1 张证据并执行 1 次目标动作；再次返回相同状态时立即停止重试，记录 Route Deviation，不得连续截图、轮询首页或盲点按。
- 每个生产批次必须输出 manifest，至少包含：输入基准、输出文件、媒体参数、精确切点、最小验证证据、未解决问题和 `capcut_touched`。主 Agent 直接复用 manifest，不重复抽帧或 `ffprobe`。

### 4. 最小有效验证预算

| 阶段 | 最多执行 | 最小证据 |
|---|---:|---|
| 字形／字幕／构图设计 | 每类 1 次 | 1 张静态预览 |
| 同类批量素材 | 每类 1 次 | 1 张代表帧；只有独有风险镜头单独加验 |
| 媒体参数 | 批次 1 次 | 批量脚本汇总分辨率、帧率、编码和时长 |
| CapCut 素材绑定 | 草稿 1 次 | 素材 ID／路径一致性断言 |
| 时间线结构 | 草稿 1 次 | 59 秒、无空档、无重叠、音频边界断言 |
| CapCut 视觉验收 | 全片 1 次 | 一次完整播放＋关键镜头定点检查 |

独有风险镜头仅包括：标准 4×4 成就聚焦、撤回 4×4 中央 Z、完整功能页、主题逐像素对齐与燃烧蜕皮、字幕左上角和片尾 Logo／网址。

### 5. 多 Agent 并行执行与单点集成

确认需求后默认使用多 Agent 并行生产，但通过文件所有权和单写入者规则保证稳定性。多 Agent 的目的是真正并行制作不同产物，不是同时审核同一内容。

#### 固定角色

| 角色 | 唯一职责 | 禁止事项 |
|---|---|---|
| 主 Agent／集成者 | 维护确认清单、分派任务、唯一修改 CapCut 草稿、最终汇总 | 不重复执行子 Agent 已完成的相同审核 |
| 棋盘素材 Agent | 标准素材锁定、其余棋盘构图、稳定起录、最终合成帧、中央 Z 素材 | 不修改功能页、主题页、字幕或 CapCut 草稿 |
| 功能与主题 Agent | 完整功能页、移动端、主题棋盘对齐、燃烧蜕皮素材 | 不修改棋盘操作素材、字幕或 CapCut 草稿 |
| 字幕与片尾 Agent | 左上角字幕参数、片尾网址、Logo 色彩取样、音频时间点清单 | 不修改视频素材或 CapCut 草稿 |

三个生产 Agent 可以并行运行。全部交付后，由其中一个已完成 Agent 切换为独立终审角色，执行一次只读审核；不额外启动多个重复审核 Agent。

#### 单写入者合同

- 只有主 Agent 可以打开、修改或保存活动 CapCut 草稿。
- 子 Agent 只生成独立素材文件、静态预览或绑定清单，必须声明 `capcut_touched=false`。
- 同一个脚本、素材文件或文档在同一时刻只能归一个 Agent 修改；任务有重叠时不得并行启动。
- 每个 Agent 的任务必须写明：输入基准、输出文件、验收条件、禁止触碰范围。
- 子 Agent 完成时只报告一次：生成文件、实际改动、最小验证结果和未解决问题。

#### 并行门禁

- 需求清单未确认：不得启动生产 Agent。
- 两个任务会写同一文件：改为串行或由主 Agent 合并。
- 上游基准发生变化：立即停止依赖旧基准的 Agent，不允许继续生成后再审核。
- 生产 Agent 尚未全部完成：不得提前启动全片审核。
- 一个 Agent 已验证且输入未变化：其他 Agent 和主 Agent不得重复验证。

#### 稳定性失败条件

- 任一子 Agent 修改了 CapCut 草稿：停止集成，恢复到修改前备份，并记录 Route Deviation。
- 输出文件未声明基准或验收条件：视为不可用，不进入素材池。
- 两个 Agent 生成相互冲突的同名文件：两份都不绑定，由主 Agent根据确认清单重新指定唯一产物。
- 审核发现问题：只退回对应产物的所有者，不重跑无关素材和全片审核。

### 6. 草稿和版本纪律

- 一个确认周期只维护一个活动草稿；不得为每次小调整创建新草稿编号。
- 只有活动草稿被 CapCut 旧内存会话占用、存在不可恢复覆盖风险时，才创建一次隔离副本，并在 `execution-notes.md` 的 `Route Deviation` 中记录原因。
- 未经确认的素材可以保留为旁路文件，但不得加入 CapCut 素材索引或主时间线。
- 不因文件名带有 `v2`、`v3`、`v4` 就推断其已获用户确认；批准状态必须来自文档中的明确记录。

### 7. 错误与正确示例

错误：先把所有页面统一放大、录制、转码、绑定，再让用户检查构图；之后对每个错误版本重复制作联系表和 JSON 审计。

正确：先分别确认“棋盘近景”“完整功能页”“主题棋盘”三类代表帧；批准后批量生成，只在最终草稿中做一次绑定检查和一次实机播放。
