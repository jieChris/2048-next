# 实施清单

> 当前仅为计划。用户明确批准实施前，不启动迁移、不修改业务代码、不处理线上数据。

## A. 记录纪元隔离

- [x] 已确认切换时主动删除中的记录继续原删除流程，不恢复为内测档案。
- [x] 已确认只隔离服务器玩家游戏记录；本地历史、石头专题、接力及人工旧榜保持不变。
- [x] 已确认切换前开始的排位局可继续完成，但结果仍归入内测。
- [x] 已确认内测档案继续公开可见，并保留公开详情、回放与导出。
- [ ] 在 `2048-game-api` 新增下一号 PostgreSQL 迁移：`records.record_era` 与 `ranked_sessions.record_era`，既有值和安全默认值均为 `beta`，约束允许 `beta | official_v1`。
- [ ] 迁移中清空 `leaderboard_best`，清理由内测成绩派生的成绩型成就及其展示槽；不删除记录或回放。
- [ ] 新排位 session 显式写 `official_v1`，排位记录从 session 继承；新版普通在线记录显式写 `official_v1`，历史导入与旧服务继续落为 `beta`。
- [ ] 给排行榜刷新、排行榜查询、玩家汇总、模式汇总、里程碑、速度统计及成绩型成就统一加入正式纪元条件。
- [ ] 玩家记录列表返回 `record_era`，回放读取继续允许内测记录；内测记录的删除/恢复接口返回只读错误。
- [ ] 更新 OpenAPI 与前端类型。
- [ ] 玩家记录列表和详情增加“内测成绩”标签，保留回放与导出，导出内容携带纪元；隐藏内测记录修改操作。

## B. 最小验证

- [ ] 数据迁移测试：迁移前仍有效的记录全部成为 `beta`，记录数、回放引用和原始字段不变；删除中的记录不被恢复。
- [ ] API 测试：加入极高分内测记录后，个人统计、PB、各榜单、里程碑和成绩型成就结果不变，但历史列表、详情和回放仍可访问。
- [ ] 会话边界测试：切换前 session 在切换后提交仍为内测，切换后新 session 才产生正式记录，客户端不能伪造纪元。
- [ ] 权限测试：内测记录不可删除或恢复；正式记录保持现有行为。
- [ ] 派生数据测试：旧榜单缓存与内测成绩型成就被移除，事件型/人工成就保留。
- [ ] 前端测试：公开访问时标签、详情、回放与导出可用，所有者视图中修改按钮不出现。
- [ ] 运行相关单元测试、类型检查与构建；记录迁移前后不变量查询结果。

## C. Rating 前置数据

- [ ] 在现有 `ranked_sessions` 状态流上记录正式尝试结果，覆盖完成、主动退出、重开和确认的基础设施故障。
- [ ] 确保玩家隐藏记录不会删除 Rating 尝试；未开始 session 与基础设施故障不计分。
- [ ] 只用 `official_v1`、`standard_4x4_pow2_no_undo` 的可信 ranked 尝试形成回测集。

## D. Rating 标定与发布

- [ ] 用时间切分比较 PB、B10、截尾均值和收缩均值，选择窗口、先验强度、最低样本量与不确定性阈值。
- [ ] 冻结模型版本、总体中心和参考分布；实现 `1500 + 200 × z` 映射。
- [ ] API 在未达公开门槛时只返回 `rating = null`、`insufficient_data`。
- [ ] 界面未达门槛时只显示“数据积累中，暂无 Rating”。
- [ ] 通过留出预测、敏感性与排名稳定性验证后，再申请上线批准。

## 风险与回滚点

- 纪元过滤漏一处就会污染正式统计；上线前必须覆盖所有 `records` 聚合与派生写入路径。
- `leaderboard_best` 和成绩型成就是派生数据，可清空后重建；原始记录和回放不可作为回滚手段删除。
- 若迁移后记录数、回放引用数或内测档案可访问性下降，立即停止切换并从备份恢复，不继续发布 Rating。
