# 实施清单

> 用户已批准在工作区实施和本地验证。正式发布前不得运行线上迁移、处理线上派生数据或启用正式纪元。

## 实施就绪度

- **可立即开发并验证**：A、B 两节的记录纪元隔离、内测档案展示、正式统计过滤及测试；开发期间不得执行线上迁移。
- **可随正式版本启用**：C 节的正式排位尝试采集；它负责积累以后标定 Rating 所需的原始事实，不预设评分参数。
- **尚不能启用数值 Rating**：固定有效表现基准 `B`、窗口长度、先验强度、最低样本量和不确定性阈值尚未冻结；正式数据只用于验证模型，不用于定义整体玩家基准。

## D. Rating 标定与发布

- [ ] 定义并冻结项目固定有效表现基准 `B`；它不得取自整体玩家均值或随玩家数量变化。
- [ ] 用时间切分比较 PB、B10、截尾均值和固定基准收缩均值，选择窗口、先验强度、最低样本量与不确定性阈值。
- [ ] 冻结模型版本并实现 `rating = 1500 + 200 × (skill - log1p(B)) / ln(2)` 映射。
- [x] API 在未达公开门槛时只返回 `rating = null`、`insufficient_data`。
- [x] 界面未达门槛时只显示“数据积累中，暂无 Rating”。
- [ ] 通过留出预测、敏感性与排名稳定性验证后，再申请上线批准。

## 风险与回滚点

- 纪元过滤漏一处就会污染正式统计；上线前必须覆盖所有 `records` 聚合与派生写入路径。
- `leaderboard_best` 和成绩型成就是派生数据，可清空后重建；原始记录和回放不可作为回滚手段删除。
- 若迁移后记录数、回放引用数或内测档案可访问性下降，立即停止切换并从备份恢复，不继续发布 Rating。
- 当前兼容策略允许缺少 schema version 的客户端继续创建 `beta` 会话。它优先防止旧客户端和旧 pending payload 污染正式统计，但也允许玩家主动选择非正式局；数值 Rating 上线前必须评估是否关闭无版本 ranked session，或显式区分 rated/unrated 入口。
