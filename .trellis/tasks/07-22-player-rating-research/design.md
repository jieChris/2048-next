# 玩家 Rating 与记录纪元设计

## 设计边界

本设计先建立可信的正式数据边界，再实现 Rating。内测成绩只作为玩家可见的只读档案；正式统计、参数标定和 Rating 只读取正式纪元。当前允许在工作区实现和本地验证，但不迁移线上数据库、不启用线上正式纪元。

隔离对象限定为 2048next 服务器权威 `records` 及其派生统计。本地浏览器历史、`stone_2k_runs`、`relay_cases` 和人工维护/导入旧榜不使用这套纪元字段，保持现状。

## 记录纪元

- 在权威 `records` 表增加一个明确的 `record_era` 字段，首版只允许 `beta` 与 `official_v1`。
- 在 `ranked_sessions` 增加同样受约束的 `record_era`；既有 session 与记录迁移为 `beta`，字段安全默认值也保持 `beta`。
- 新版客户端在申请排位 session 时声明受支持的 attempt schema version；服务端只为当前版本签发 `official_v1`，旧客户端或缺少版本的请求仍签发 `beta`。提交排位成绩时从 session 继承纪元，切换前已开始的排位局即使之后提交也仍是内测成绩。
- 无排位 session 的在线普通记录只有携带当前 record schema version 才写入 `official_v1`；缺少版本的旧客户端与正式发布后才重试的旧 pending payload 仍归入 `beta`，宁可少计也不误计。
- 纪元完全由服务端确定，不接受客户端字段，也不根据提交时间推断。
- 不另建纪元表、赛季服务或动态配置；需要第二个正式纪元时再新增允许值和切换逻辑。

## 读取边界

只有玩家历史是双纪元读取：

- `/api/user/:id/records` 返回内测与正式记录，并返回 `record_era`。
- 回放详情继续按记录 ID 读取；内测记录的详情、回放与导出保持可用。
- 前端在列表与详情显示“内测成绩”标签，导出内容携带 `record_era`。
- 历史接口与回放继续保持公开访问，不因纪元切换新增登录限制。
- 生效中的内测记录不显示删除操作，后端也必须拒绝新删除，不能只依赖界面隐藏。切换时已软删除且仍在原恢复期限内的记录保留恢复操作；恢复后成为只读内测档案。

所有成绩统计只读取 `record_era = 'official_v1'`：

- 玩家汇总、按模式汇总、PB、里程碑与速度统计。
- 分数榜、周期榜、速度榜及 `leaderboard_best` 的刷新和重建。
- 成绩型成就的即时授予与回填。
- 后续 Rating 的可信尝试、固定基准模型和回测验证。

分页所需的历史记录总数仍可包含内测记录，因为它只描述档案列表，不作为实力指标展示。

## 派生数据切换

- `leaderboard_best` 只是一张可重建缓存。切换时清空现有内容；之后仅由正式记录刷新。
- 删除由内测记录产生的 `user_achievements` 成绩型派生项，并先清理对应展示槽。保留 `event`、`manual` 等不依赖成绩的成就，包括独立授予的内测纪念类成就。
- 不删除或改写 `records`、`replay_objects` 与回放文件。
- 玩家在切换前已经主动删除、仍处于恢复期限内的记录不恢复，继续原删除流程；纪元切换不能撤销玩家的删除选择。

## Rating 数据流

Rating 第一版仅处理 `standard_4x4_pow2_no_undo` 的正式、可验证 ranked 尝试：

```text
正式 ranked 尝试
  -> 最近固定窗口
  -> x = log1p(score)
  -> 20% 截尾均值
  -> 向项目固定基准 b = log1p(B) 做样本量收缩
  -> rating = 1500 + 200 × (skill - b) / ln(2)
  -> 同时满足最低样本量与不确定性阈值后公开
```

`B` 是项目定义并随模型版本冻结的有效表现基准，不取整体玩家均值，也不随玩家数量变化。1500 表示达到 `B`；稳定有效表现约翻倍时增加 200 分，约减半时降低 200 分。正式纪元数据只用于验证窗口长度、收缩强度、公开阈值和预测稳定性，不用于动态移动 `B`。数据不足时 API 返回 `rating = null` 与 `insufficient_data`，界面只显示“数据积累中，暂无 Rating”。

正式 Rating 直接复用现有 `ranked_sessions` 作为不可变尝试账本，不新建表：

```text
created（已签发但未开始）
  -> 首次成功移动经服务端验证 -> started
  -> started 后完成终局 -> consumed
  -> started 后主动退出/重开 -> abandoned
```

- 新接口 `POST /api/ranked-session/attempt` 只接受 `begin | abandon`、session token、精确模式和 replay；不接受客户端提供的纪元、分数、结果或基础设施故障声明。
- 服务端验证 token、用户、seed、challenge 与 replay。`begin` 至少包含一次成功移动；`abandon` 必须是非终局 replay，并由服务端派生分数、最大方块、步数与用时。
- 如果 `begin` 上报丢失，但合法的 abandon/终局 replay 已证明发生过移动，可原子补记开始时间再完成状态转换。
- 完成与放弃的验证摘要写入 session `server_context`，因此玩家隐藏或物理清理可见记录不会抹去 Rating 尝试。
- `created` 到期且没有开始证据时不计 Rating；`started` 到期且无终局时派生为未知中断，不能由玩家自报为基础设施故障。基础设施豁免只能由服务端或管理员确认并留审计记录。
- 前端在首次成功移动和确认重开后，将事件先写入本地 outbox 再上传；失败可重试。普通 `pagehide` 不能证明主动退出，只用于冲刷已明确产生的事件。
- 客户端 schema version 只表示协议能力；score、outcome、纪元及验证摘要始终由服务端验证或派生，客户端不能通过声明版本取得数据权威。

## 兼容与发布顺序

正式版本上线本身就是唯一切换点，不设置历史切分日期，也不提前改变线上数据。

1. 发布前在隔离环境完成实现、备份方案、迁移预演和验证；线上仍按内测规则运行。
2. 正式发布时增加纪元字段，把既有记录和 session 标为内测，清理可重建的正式统计派生物。
3. 在同一次发布中部署签发正式纪元 session、提交时继承纪元、统一过滤统计并展示内测标签的 API 与前端。
4. 校验原记录数与回放引用未减少，正式榜单和统计为空或仅含切换后的记录。
5. 收集正式尝试；固定基准模型通过个人稳定性、留出预测和放弃惩罚验证前不发布 Rating。

回滚时可停用新版展示和统计，但不得把内测记录改成正式记录。派生榜单与成绩型成就可从正式记录重新生成。

当前兼容策略允许缺少 schema version 的旧客户端继续获得 `beta` session，优先保证旧 pending payload 不污染正式统计。代价是客户端也可主动选择非正式局；在数值 Rating 上线前，必须用正式数据评估这一选择偏差，并决定是否拒绝无版本 ranked session，或显式提供 rated/unrated 入口。该选择偏差只影响玩家自身样本完整性，不参与固定基准的定义。

## 刻意保持简单

- 不新增服务、依赖、纪元管理后台或统计缓存表。
- 不新增 Rating attempt 表，直接复用 `ranked_sessions` 的状态、时间、`final_record_id` 与 `server_context`。
- 不为首版增加纪元筛选器或单独的内测档案页面；现有记录列表加标签即可。
- 不为 `record_era` 新建索引，只有查询计划或延迟证明需要时再加。
- 不把其他独立成绩源顺带迁入这套纪元模型。
