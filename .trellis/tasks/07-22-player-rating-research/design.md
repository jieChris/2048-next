# 玩家 Rating 与记录纪元设计

## 设计边界

本设计先建立可信的正式数据边界，再实现 Rating。内测成绩只作为玩家可见的只读档案；正式统计、参数标定和 Rating 只读取正式纪元。当前仍是规划阶段，不修改业务代码或数据库。

隔离对象限定为 2048next 服务器权威 `records` 及其派生统计。本地浏览器历史、`stone_2k_runs`、`relay_cases` 和人工维护/导入旧榜不使用这套纪元字段，保持现状。

## 记录纪元

- 在权威 `records` 表增加一个明确的 `record_era` 字段，首版只允许 `beta` 与 `official_v1`。
- 在 `ranked_sessions` 增加同样受约束的 `record_era`；既有 session 与记录迁移为 `beta`，字段安全默认值也保持 `beta`。
- 新版服务签发的排位 session 显式写入 `official_v1`，提交排位成绩时从 session 继承纪元。切换前已开始的排位局即使之后提交，也仍是内测成绩。
- 无排位 session 的新版在线普通记录由服务端显式写入 `official_v1`。迁移完成到新版服务上线之间产生的记录仍归入内测，宁可少计也不误计。
- 纪元完全由服务端确定，不接受客户端字段，也不根据提交时间推断。
- 不另建纪元表、赛季服务或动态配置；需要第二个正式纪元时再新增允许值和切换逻辑。

## 读取边界

只有玩家历史是双纪元读取：

- `/api/user/:id/records` 返回内测与正式记录，并返回 `record_era`。
- 回放详情继续按记录 ID 读取；内测记录的详情、回放与导出保持可用。
- 前端在列表与详情显示“内测成绩”标签，导出内容携带 `record_era`。
- 历史接口与回放继续保持公开访问，不因纪元切换新增登录限制。
- 内测记录不显示删除或恢复操作；后端也必须拒绝修改，不能只依赖界面隐藏。

所有成绩统计只读取 `record_era = 'official_v1'`：

- 玩家汇总、按模式汇总、PB、里程碑与速度统计。
- 分数榜、周期榜、速度榜及 `leaderboard_best` 的刷新和重建。
- 成绩型成就的即时授予与回填。
- 后续 Rating 的样本、参考分布和模型回测。

分页所需的历史记录总数仍可包含内测记录，因为它只描述档案列表，不作为实力指标展示。

## 派生数据切换

- `leaderboard_best` 只是一张可重建缓存。切换时清空现有内容；之后仅由正式记录刷新。
- 删除由内测记录产生的 `user_achievements` 成绩型派生项，并先清理对应展示槽。保留 `event`、`manual` 等不依赖成绩的成就，包括独立授予的内测纪念类成就。
- 不删除或改写 `records`、`replay_objects` 与回放文件。
- 玩家在切换前已经主动删除、仍处于恢复期限内的记录不恢复，继续原删除流程；纪元切换不能撤销玩家的删除选择。

## Rating 数据流

Rating 第一版仅处理 `standard_4x4_pow2_no_undo` 的正式、可验证 ranked 尝试：

```text
正式 ranked 尝试
  -> 最近固定窗口
  -> x = log1p(score)
  -> 20% 截尾均值
  -> 向冻结总体中心做经验贝叶斯收缩
  -> 按冻结参考分布映射为 1500 + 200 × z
  -> 同时满足最低样本量与不确定性阈值后公开
```

阈值、窗口长度和收缩强度只能用正式纪元数据做时间切分回测后冻结。数据不足时 API 返回 `rating = null` 与 `insufficient_data`，界面只显示“数据积累中，暂无 Rating”。

正式 Rating 还需要完整保存主动退出、重开和完成结果。优先扩展现有 `ranked_sessions` 状态流作为不可变尝试账本；只有现有结构无法表达经验证的最终进度时，才考虑新表。

## 兼容与发布顺序

1. 备份并预演迁移。
2. 增加纪元字段，把既有记录标为内测，清理可重建的正式统计派生物。
3. 部署签发正式纪元 session、提交时继承纪元、统一过滤统计并展示内测标签的 API 与前端。
4. 校验原记录数与回放引用未减少，正式榜单和统计为空或仅含切换后的记录。
5. 收集正式尝试；达到回测所需覆盖前不发布 Rating。

回滚时可停用新版展示和统计，但不得把内测记录改成正式记录。派生榜单与成绩型成就可从正式记录重新生成。

## 刻意保持简单

- 不新增服务、依赖、纪元管理后台或统计缓存表。
- 不为首版增加纪元筛选器或单独的内测档案页面；现有记录列表加标签即可。
- 不为 `record_era` 新建索引，只有查询计划或延迟证明需要时再加。
- 不把其他独立成绩源顺带迁入这套纪元模型。
