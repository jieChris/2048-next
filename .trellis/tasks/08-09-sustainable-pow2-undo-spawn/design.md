# 设计

## 规则模型

### 幂二

移动后出块前，扫描所有非阻挡格，用 `BigInt` 累加盘面总和 `S`。当已占用 `N-1` 格且 `popcount(S)=N-1` 时，强制值为所有非空方块的全局最小值。

不扫描空格邻居，不进行几何可合并性判定。`popcount(S)` 小于阈值时从当前动态池取值。

### 斐波那契

令已解锁的连续出数前缀为 `F1...Fd`。合成 `Fr` 的最小峰值格数满足：

- `C_d(r)=1`，当 `r≤d`；
- `C_d(r)=max(C_d(r-1),1+C_d(r-2))`，当 `r>d`。

递推解为 `C_d(r)=1+ceil((r-d)/2)`，因此 `N` 格的当前上限为 `R=d+2(N-1)`。不解锁新值时 `C_d(R+1)=N+1`；解锁 `F(d+1)` 后 `C_(d+1)(R+1)=N`，所以它是突破下一阶所必需的最小新出数。

实现从 `spawnValueCounts` 中取大于 2 的合法斐波那契出数，从 `F3` 开始计算连续前缀的最高阶 `d`。对当前 `N-1` 个非空值排序，与期望前沿列表比较：

`F(d+2),F(d+4),...,F(d+2(N-1))`

只在列表精确相等时强制 `F(d+1)`。不使用 Zeckendorf 项数、总和、当前最大块或“有无合法对”作为替代阈值。

该判定与幂二一样忽略几何位置。强制值加入后，前沿中的下一组相邻阶位对始终保留在多重集中；每次合并后新生成的普通块不影响这一代数结论。

## 常驻概率

动态出数表只有两种状态：

| 规则 | 未解锁高阶值 | 已解锁 `k>0` 个高阶值 |
| --- | --- | --- |
| 幂二 | 2=90%，4=10% | 2=87%，4=10%，每个高阶值=`3%/k` |
| 斐波那契 | 1=90%，2=10% | 1=87%，2=10%，每个高阶值=`3%/k` |

临界强制值优先于随机表。普通随机与排位确定性 value roll 共用相同的有序区间，避免端侧边界不一致。解锁值按数值升序进入共享 3% 区间。

## Web 状态与数据流

复用 `manager.spawnValueCounts`，不新增持久化字段：

- 幂二取计数大于 0、大于 4 且为 2 的幂的值。
- 斐波那契取计数大于 0、大于 2 且为合法斐波那契项的连续前缀。
- `recordSpawnValue` 在首次强制出数后自动更新该状态。
- 撤回快照不包含该计数，存档恢复包含该计数，符合“本局一旦解锁就常驻”。

出块共同流程为：选择落点→计算当前解锁集→检查规则对应的精确容量阈值→强制值或动态概率取值→记录出数。主随机和排位确定性路径调用同一规则函数。

## 回放与 API 权威验证

RPL1 ext type 8 与 ULEB128 编码不变。语义扩展为“当前规则集的精确高阶出数”：

- 幂二只接受安全整数范围内、大于 4 的 2 的幂。
- 斐波那契只接受安全整数范围内、大于 2 的斐波那契项。
- 扩展必须紧邻相应 move，move 的基础 value bit 保持 0。

API 按记录顺序维护不随 undo 回滚的解锁集：

1. 幂二临界盘只允许全局最小值；斐波那契容量前沿只允许 `F(d+1)`。
2. 非临界盘只允许基础值或已解锁值。
3. 排位确定性验证使用同一 87/10/共享 3% 表和区间顺序。
4. 未解锁精确值、非法数列值、重复扩展或错误配对均拒绝。

验证语义变更后将 `verification_version` 从 4 提高到 5。旧回放未使用新扩展语义时保持可解码。

## 风险与回退

- 前端和 API 使用相同的排序、累计区间和严格比较边界，防止 3% 等分的浮点差异。
- 恢复旧存档时，幂二合法高阶出数直接视为已解锁；斐波那契只采用从 `F3` 开始的连续合法前缀，避免损坏值跳级解锁。
- 不新增数据库或本地存档字段；回退代码时旧存档仍可读。
- Android 受共享源管理规约限制，本轮不直接修改受管规则文件。
