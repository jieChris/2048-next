## 验证记录

- 数学边界：对幂二方块总和 `S`，`popcount(S)` 等于充分进位后的最少方块数；移动后最多占用 `N - 1` 格，因此 `popcount(S) = N - 1` 必然对应唯一空格的容量临界盘。
- 发现并修正原提案的几何反例：全局最小方块可能不与空格相邻。救援值改为唯一空格四邻中的最小值，确保生成后立即存在合法合并；无四邻值时才回退全局最小值。
- 上述邻居救援是第一版已实现行为，后被用户明确否决；最终幂二需求是全局最小值，不考虑几何可合并性。

## 斐波那契规则演算（规划阶段）

- 用户反例 `2,3,5,5` 证明“出数前一个空格且无合法对”错把可撤回的错误分支当成容量不足；该候选已废弃。
- 按实际节奏建模：单块每次移动最多合并一次，成功移动后立即生成一块，撤回恢复出数前的上一步整盘。
- 当直接出数已连续解锁到 `Fd` 时，最小峰值格数递推得 `C_d(r)=1+ceil((r-d)/2)`，`N` 格当前上限为 `F(d+2(N-1))`。
- 有限多重集状态搜索将每次合并后的常规出数纳入转移；`N=2..5`、`d=2..5` 均可达精确前沿 `{F(d+2),F(d+4),...,F(d+2(N-1))}`，强制 `F(d+1)` 后当前可达最高阶恰从 `d+2(N-1)` 提高到下一阶。
- 用户最终确认不救援可撤回分支，只在旧出数池刚好无法突破下一阶的精确容量前沿加入新数字。

## 最终实现

- Web 幂二与斐波那契可撤回模式共用现有出块入口；幂二临界盘强制全局最小值，斐波那契只在连续解锁前缀对应的精确容量前沿强制下一直接出数。
- 已解锁高阶值继续复用 `spawnValueCounts`，基础值保持 87%/10%，所有高阶值等分固定 3%；普通随机与排位确定性出数共用同一整数权重表。
- RPL1 ext type 8 与 ULEB128 格式保持不变，Web 与 API 均按当前规则集接受精确幂二或斐波那契高阶值。
- API 按回放事件顺序维护独立解锁集合，不将其放入撤回快照；权威校验版本提升到 5。
