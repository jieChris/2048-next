## Route Deviation

- 为闭合阶段 2.2B 的真实 PostgreSQL 门禁，本机通过 Homebrew 安装 `postgresql@17` 17.10；公式下载与安装完成，但 post-install `initdb` 被 macOS 系统策略拒绝加载 `icu4c@78` 的动态库，报告代码签名无效。采用最保守回退：不关闭系统安全策略、不对第三方动态库强制改签、不把 mock 当真实数据库；最终使用隔离的受信 PostgreSQL 17.10 运行时 `/tmp/2048-next-pg17-runtime` 建立仓库外测试集群并完成迁移、回填、索引和账号删除真实验证。未修改系统安全策略、未启动生产服务、未接触生产数据。
- 阶段 5 的 API 29 基准镜像使用 Android WebView 91；Playwright `connectOverCDP` 建立浏览器级连接时会自动调用该旧 WebView 不支持的 `Browser.setDownloadBehavior`，并以“Browser context management is not supported”中止，无法用浏览器级封装采集当前原生包证据。采用最保守回退：继续连接同一 debug WebView 暴露的页面级 DevTools socket，直接使用原始 CDP 的 `Runtime`、`Network` 与 `Input` 域完成 DOM、IndexedDB、真实触摸和零业务网络断言；不修改 App 源码、WebView 配置、原生资产或验收条件，也不以桌面 Chromium 结果替代 API 29。
- 仓库存在 `.trellis/spec` 与 `.trellis/tasks`，但缺少技能约定的 `.trellis/scripts/task.py`，无法执行标准任务创建命令。采用最保守回退：按现有 `MM-DD-slug` 目录格式手工创建本规划任务；未启动实现，也未修改产品代码。
- `trellis-before-dev` 约定的两仓库 `.trellis/scripts/get_context.py` 与 `.trellis/spec/guides/index.md` 均不存在。采用最保守回退：手工枚举并完整阅读前端现有三份 spec、后端现有两份 spec 与两仓库 `AGENTS.md`；未跳过任何已存在规范。
- 已批准设计原写为“撤回恢复 RNG 步号、计时和回放游标”，但冻结既有 Web 行为与服务端 verifier 时确认 RPL1 将撤回视为动作：有效局面回退，已经经过的时间与动作流不回拨，并消耗一个 RNG action step。为避免破坏既有回放、排位验证和跨端确定性，采用最保守兼容规则并以共享黄金 fixture 固化；影响仅是撤回后的下一次出块不会复用被撤销分支的 RNG 位置，产品可见棋盘/分数/步数等状态仍正确恢复。
- 已批准 Android 权限基线预期合并清单只有 `INTERNET` 与 `VIBRATE`，但 Capacitor 8.4.2 使用的 AndroidX Core 1.17.0 会为 `ContextCompat` 的非导出动态广播自动合并 `${applicationId}.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`，并以 `protectionLevel=signature` 声明/自用。真实 debug APK 的 `apkanalyzer` 已确认该来源；强行通过 manifest removal 删除会破坏 API 29 兼容并削弱同签名隔离。采用最保守回退：允许且仅允许 `INTERNET`、`VIBRATE` 以及与当前 debug/release application ID 完全匹配、保护级别严格为 signature 的这一项自有权限；审计继续拒绝通知、存储及任何其他权限。影响是原“只有两项”的字面计数变为两项平台权限加一项应用私有签名权限，不扩大对系统或其他应用的数据访问能力。
- API 29 基准镜像自带 Android WebView 91；Capacitor 8.4.2 内置 `SystemBars` 会在该旧 WebView 的 `document.documentElement` 创建前抢先注入安全区 CSS，断网冷启动稳定产生 `Error injecting safe area CSS`，但随后页面仍正常加载。全局关闭会破坏 Android 15/16 强制 edge-to-edge 的安全区，直接修改 `node_modules` 又会削弱可重复安装。采用最保守分层回退：生成配置继续固定 `SystemBars.insetsHandling=css`，Android 15+ 沿用官方 CSS insets；`MainActivity` 仅在 API 29–34 的运行时配置中关闭该注入，并由已批准的官方 `StatusBar` 以 `overlaysWebView=false` 将内容放在状态栏下方。移动 CSS 同时消费 Capacitor `--safe-area-inset-*` 与标准 `env()` fallback。影响仅是旧 Android 使用 fitted content、新 Android 使用 edge-to-edge；不修改游戏页面结构、不增加权限或依赖。
- 阶段 4 开发前的 IndexedDB v1 尚未进入任何 APK、公开版本或用户数据，但其 `cache` 单字段主键不能从数据库层保证多账号同名逻辑键隔离。采用发布前基线修正：物理版本升至 v2，在单个原生 `versionchange` 事务内把测试 v1 cache store 改为 `[ownerKey, cacheKey]` 复合主键并保留原行；任一复制失败会由 IndexedDB 原子回滚到完整 v1，未来 row schema 不改写。该预发布迁移因此包含一次 store 重建，而不是发布后的纯加法升级；首个公开版本直接创建 v2，后续正式 schema 仍严格执行 expand/contract，不以此先例重建已发布数据。
- 阶段 3.3 计划文字写为 Kotlin 测试，但受控 `app` module 与 `MainActivity` 当前均使用 Java；只为约 200 行安全桥引入第二种 App 源码语言会增加插件、编译与审计面。采用最保守回退：桥和 Android 仪器测试均使用 Java，继续直接调用相同 Android Keystore API，并限定所有原生门禁为 `:app:*`。功能合同、API 29 下界与加密方案不变，未增加依赖。
