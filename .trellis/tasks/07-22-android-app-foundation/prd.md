# Android App 基底规划

## 目标与用户价值

- 建设一个专门面向 Android 的 2048 App，而不是把现有网页版简单塞入 WebView 或逐页做响应式适配。
- App 使用独立的信息架构、页面入口、导航、交互与视觉体系，同时复用现有经过验证的游戏规则、回放契约和后端 API。
- 长期产品形态为 Web、Android App、微信小程序三端并存；三端独立发布和呈现，共用同一个账号体系、游戏后端与云端业务数据。
- 在首个功能版本之前先建立清晰、可测试、可演进的基底，使后续模式扩展、线上能力和长期维护不依赖脆弱的旧脚本加载顺序。
- 优先保证启动速度、对局流畅度、离线可靠性、进程恢复、数据一致性和可诊断性。

## 已确认事实

- 用户接受以 Capacitor 作为 Android 容器，但要求制作专属 App，不接受把现有网页原样封装后作为最终产品。
- App UI 沿用现有 Vite + TypeScript 工具链，首版不新增 React 等 UI 框架；移动端代码与独立构建配置放在 `2048-next` 同一仓库，以便原子复用和迁移共享游戏核心。
- App 的页面、入口和导航将与现有 Web 多页面结构基本不同。
- 首个公开版本只交付玩家核心产品：主页、玩法入口、对局、结果、历史/回放、账号、排行榜、成就和基础设置。
- 管理后台、接力工具、2K 监控、完整色板编辑和实验模式不进入首个公开版本，但基底不得阻塞后续以独立模块加入。
- 用户确认 Web、Android App、微信小程序三端需要长期保留，并共享同一个后端与可同步的用户数据。
- 产品实施顺序确定为先完成 Android App；微信小程序的产品与身份接入留到 Android App 稳定后另行规划。
- 游客无需登录即可游玩 `standard_4x4_pow2_no_undo`（标准 4×4、不可撤回）；进入其他游戏模式前必须完成登录。
- App 顶层采用“首页 / 模式 / 记录 / 我的”四项底部导航；对局、结算、回放和登录注册流程隐藏底部导航，排行榜暂不单独占用导航项。
- 游客标准局历史只保留在本机并标记为游客记录；登录时不自动上传或并入账号云历史，登录后的新记录才按账号规则同步。
- 首版游戏范围确定为三个模式：标准 4×4 不可撤回、经典 4×4 可撤回、标准 3×3 不可撤回；后两者要求登录。
- App 使用全新的本地数据空间；首版不自动迁移 Web 的 localStorage/IndexedDB 历史，登录后只读取账号已有云记录。
- 首版最低支持 Android 10（API 29）；编译与 target SDK 使用开发时 Capacitor 支持且符合发布要求的最新稳定版本。
- 首版锁定竖屏，不提供手机横屏页面；横屏能力仅在后续有明确需求时单独设计和测试。
- 首版正式支持安卓手机；平板和折叠屏允许安装运行，但仅使用居中的手机宽度兼容布局，不承诺专属大屏体验。
- App 不以 60 FPS 作为渲染上限；刷新策略确定为自动跟随系统实际的 60/90/120Hz，在 90Hz 及以上设备支持 90+ FPS 棋盘动画，并允许省电、温控或系统设置主动降频。
- 首页定位确定为快速开局页，不建设账号动态、资讯流和运营内容综合大厅。
- 设备曾成功登录且未主动退出时，断网仍可进入三个首版模式；联网且取得排位会话时默认作为排位对局，否则自动降为明确标记的离线普通对局。
- 为同时保证排位取得时间由服务端证明且棋盘输入不等待网络，无存档的在线排位准备发生在棋盘展示前：服务端按稳定 operation ID 幂等创建并返回冻结的 `started_at/seed/token`，App 安全保存成功后才展示“排位”棋盘；有界失败则直接展示“离线对局”棋盘，不出现第三种对局状态。排位计时从服务端 `started_at` 连续计算，normal/游客局仍由第一次有效移动启动；棋盘一旦可操作，首步及后续滑动都不得等待网络。
- App 在同一进程从后台恢复时直接返回正在进行的对局；进程被系统结束后的冷启动先进入首页，并通过“继续游戏”恢复持久化对局。
- Android 正式显示名称为 `2048 NEXT`，application ID 为 `cn.next2048.app`；application ID 作为安装、签名、升级和应用链接的稳定身份，上架后不得更改。
- App 按正常公开产品运行，不展示封闭内测、受邀邮箱或 beta notice 流程；任何符合规则的邮箱都可通过邮箱验证码注册并使用邮箱密码登录。
- 首次启动显示单页隐私选择而非轮播引导：用户可“同意并继续”启用完整联网能力，或选择“仅离线体验”进入游客标准 4×4。未同意前不得发起业务网络请求或初始化第三方统计；用户以后主动进入联网功能时再次请求同意。
- 首个对外分发版本由官网提供正式签名 APK，同时持续构建兼容应用商店的 AAB；首版不接商店专属 SDK 或应用内更新框架，更新通过同包名、同签名的新版 APK 覆盖安装。
- 账号删除采用 72 小时冷静期：申请后进入待删除状态；期限内使用邮箱和密码重新登录会取消删除，超过期限仍未登录则彻底删除该用户及其游戏数据。
- 首版跨端同步只覆盖账号资料、已结束记录与回放、排行榜和成就；未结束对局仅在产生它的设备本地恢复，不承诺 Web 与 App 跨设备续玩。
- 每台设备允许不同模式并行保留未结束存档；首页“继续游戏”恢复最近一次退出的未结束模式，其他模式存档继续保留并从模式页进入。
- 每个模式在设备上最多保留一个未结束存档。模式页的模式卡只有“进入该模式”这一种动作：存在存档就自动加载，不存在存档就自动创建新局；模式页不提供“新游戏”次按钮。
- 对局内“新游戏 / 重新开始”仅在当前局已有至少一次有效移动且尚未结算时要求二次确认；尚未移动或已经结算时直接开始该模式新局。
- 用户确认未结束对局不产生历史：Android 返回键或正常离开只持久化当前模式存档；对局内重新开始视为放弃当前局，确认后覆盖该模式存档，不写入本地/云历史，也不进入上传 outbox。
- 用户确认经典 4×4 可撤回模式在无路可走但仍可撤回时进入“待结算终局”，提供“撤回继续 / 结束并结算”；选择结算或已无可用撤回状态时才固化记录。两个无撤回模式在无路可走时直接结算。
- 用户确认 App 使用专属最小结算页：展示模式、最终分数、最大方块、用时、步数、个人最佳/成就反馈和异步上传状态；主操作为“再来一局”，次操作为“查看回放”和“返回首页”。
- 用户确认首版只对已结算记录提供回放文件分享/保存：结算页、历史详情和回放播放器复用同一动作，生成一种版本化回放文件并调用 Android 系统分享面板或文件保存器。
- 正常退出或切换账号后，不保留该账号在本机的多模式未结束存档、账号缓存或待上传 outbox；云端已经确认的数据不受影响，游客本地数据保持独立。
- 退出时先在有界等待内尝试上传已结束的 outbox；若仍有未上传记录或未结束模式，必须列出数量并由用户明确选择“取消退出”或“仍然退出并清除”，不得静默丢弃或无限阻止退出。
- “记录”底部页以历史记录为主体；回放依附于历史详情，不单独占用页签。排行榜不再使用 Web 游戏页内嵌展开模式，而从记录页等入口打开独立模态窗口。登录后历史可筛选账号云记录与本机游客记录，游客状态只显示本机游客记录。
- 后端现有 `/api/records` 已支持无排位令牌的已验证记录并保存为 `source: normal`；排行榜与成就只纳入排位来源，因此离线结果恢复联网后可复用现有接口同步为非排位历史。
- 当前 Web 公开排行榜页的可见指标是“分数”和“竞速”；最少步数指标已从 UI 移除。竞速仅适用于标准 4×4 无撤回，并支持按 2048/4096/8192/16384/32768 目标方块选择。
- 当前 `/leaderboard` 不返回权威名次，Web 前端只按分页数组位置显示连续的 1、2、3。后端分数榜在分数相同时继续按用时、步数和更新时间排序，竞速榜在毫秒成绩相同时继续按整局用时、步数和结束时间排序，因此公开指标相同的玩家目前也不会并列，且用户看不到决定先后的完整依据。
- 用户确定 2048 NEXT 榜单必须使用唯一连续名次，不采用并列。分数榜按分数降序；分数相同时，以该玩家首次取得这一成绩的对局结束时间 `ended_at` 升序排列，更早取得者在前。整局用时、步数和榜单缓存 `updated_at` 不再影响同分名次；若成绩与 `ended_at` 均完全相同，仅用稳定用户 ID 作为最终确定性顺序。
- 用户确认竞速榜采用同一原则：目标方块毫秒时间升序；时间相同时按首次取得该竞速成绩的 `ended_at` 升序，更早取得者在前；两项均相同时只用稳定用户 ID 保证唯一连续名次。整局用时和步数不再作为同竞速成绩的隐藏裁决字段。
- 历史迁移存在一个不可逆的数据事实：部分既有 ranked 记录缺少可信的服务端开始锚点，真实取得时刻已无法事后重建。规划采用最保守且可审计的兼容规则：只有这类旧记录以 `consumed_at/verified_at/created_at` 中最早可证明的服务端接收时间作为冻结的 `canonical_ended_at`，并记录 fallback 来源；不得继续使用客户端可控的旧 `ended_at` 决定名次或周期。具备可信 begin 锚点的旧记录及所有新记录仍按服务端开始时间加回放验证时长计算。该迁移可能使极少数无可信锚点的旧成绩按“服务端收到时间”而非无法证明的本地完成时间归入周期和同分先后，但不会删除原始记录。
- 当前游戏页内嵌 TOP 10 已支持总榜、日榜、周榜和月榜切换，而完整 Web 排行榜页只请求总榜；后端具备周期查询，但 OpenAPI 的 `daily/weekly/monthly` 与实际 Node/Web 使用的 `day/week/month` 存在契约命名漂移，移动接入前必须统一。
- 用户确认 App 首版排行榜保留总榜、日榜、周榜和月榜四个周期，默认显示总榜并仅请求当前选中的周期。
- 用户确认排行榜采用覆盖主内容与底部导航的 App 内全屏模态窗口，不启动额外 Android Activity 或系统窗口；关闭后恢复来源页面的滚动与筛选状态。
- 用户确认未结束对局中保留排行榜入口。打开排行榜时棋盘输入暂时禁用，但对局计时、排位会话和持久化生命周期继续运行，不得借此暂停竞速时间；关闭后返回同一棋盘状态。
- “盘面和”只用于 2048 NEXT 的本地历史和用户个人记录排序；App 沿用现有分层，不把它提升为全站排行榜指标。2048 NEXT 的公开 `/leaderboard` 仍只提供分数和竞速。
- `2048-next` 与 `2048-ranked` 是两个独立产品和独立前端。二者共享 `2048-game-api` 的账号身份与各自所需的后端接口，但 `2048-ranked` 的全国榜、板块、投稿和管理数据不属于 2048 NEXT，也不是 Android App 的产品范围或数据来源。
- 当前 Web 前端是 Vite + TypeScript 多页面应用；`play` 运行清单仍顺序加载 91 个 legacy 脚本。
- 当前 `EngineSession.move()` 尚不拥有完整棋盘移动、确定性出块和特殊模式状态；实际完整对局行为仍由 legacy `GameManager` runtime 驱动。
- 现有纯 TypeScript 规则、移动规划、计分、撤回、回放 codec 和数据 contracts 可作为跨端核心的迁移基础。
- `2048-game-api` 已形成独立 HTTP 边界，账号、记录、排行榜、排位会话、回放验证和持久化应继续由该服务权威管理。
- Android App 只作为 `2048-next` 的新客户端直接调用 `2048-game-api`，不得调用 `2048-ranked` 的页面、NextAuth 会话、兼容代理或全国榜接口。
- 当前后端没有微信 `openid`、`unionid` 或通用第三方身份绑定数据模型；小程序接入统一账号前需要补充身份映射能力。
- 当前 Web 登录与注册仍保留受邀邮箱封闭内测页面，但 Android App 已确定按正常公开产品运行；移动客户端不得继承 beta 页面或准入文案。
- Node/PostgreSQL 后端的 `BETA_ACCESS_GATE_ENABLED` 默认值为 `false`，公开注册、登录和验证码接口已存在；App 发布环境必须保持玩家 API 的 beta gate 关闭，不能依靠客户端伪造渠道绕过。
- 代码库目前没有正式隐私政策页面、账号删除 API 或公开账号删除网页；由于 App 允许创建账号，这些属于公开发行前的合规阻塞项。
- 后端仍保留 Worker 与 Node/PostgreSQL 两个入口；移动客户端必须固定到唯一的 Node/PostgreSQL HTTPS 生产基址。
- 当前 OpenAPI 与 Node 实现存在方法、字段和路由覆盖漂移，尚不能直接作为移动 SDK 的唯一权威来源。
- 现有账号云记录支持软删除并在 3 天内恢复，后端已提供 `DELETE /records/:id` 与 `POST /records/:id/restore`。
- 用户确认登录后在本机有界缓存最近一次成功读取的云历史页面与成就摘要；离线时只读显示并标注最后更新时间，联网刷新失败仍保留旧快照。退出或切换账号时清除对应账号快照，游客本地历史不属于云快照。
- 用户确认 App 允许删除历史。账号云记录沿用现有 3 天软删除/恢复机制并提供“最近删除”筛选；游客本地记录在二次确认后立即永久删除。离线云快照只读，不能排队删除或恢复。
- 现有成就目录包含与首版 App 无关或暂时无法在 App 完成的 Web 彩蛋、404、手工授予及未移植模式成就；当前成就契约只有规则参数，没有明确的客户端可完成平台元数据。
- 用户确认 App 显示账号已经获得的全部跨端成就；未获得列表只展示首版 App 当前可完成的成就，隐藏成就在获得前继续隐藏、获得后正常显示。客户端可完成范围必须由后端明确元数据提供，不能靠名称或规则文案猜测。
- 当前仓库没有推送服务、设备通知令牌或 Android 本地通知产品链路；用户确认首版不做推送或系统本地通知，也不申请 Android 通知权限。同步结果、成就解锁和网络状态只通过 App 内提示展示。
- 当前 Web 在窄屏提供可手动打开的操作提示弹窗；用户明确 App 不加入首次对局引导、手势动画或自动操作提示，进入棋盘后直接开始游戏。
- 当前 Web 默认在首次合成 2048 时阻塞显示胜利层，也允许通过设置改为自动继续；用户确认 App 统一采用自动继续，只显示不阻塞棋盘输入的短暂里程碑提示。
- 当前仓库没有 Sentry、Crashlytics 或自建 App 崩溃上报链路，现有 diagnostics 主要属于回放/记录数据；用户确认 App 在完成隐私同意后自动上报脱敏的崩溃与严重错误，但不接入第三方统计 SDK，也不采集页面点击、游戏行为或广告分析数据。
- 首版诊断直接提交到 `2048-game-api` 的最小化诊断接口；不得上传邮箱、昵称、Token、棋盘、回放或移动序列。“仅离线体验”状态绝不上传，设置中允许关闭自动诊断并手动导出本地诊断信息。
- 当前 Web 已有触摸与窄屏适配，但这些 DOM 页面和输入实现不是 App 页面设计的约束。
- 当前 Web 默认简体中文并支持英文切换，但翻译散落在多个 legacy runtime 和页面字典中；App 不能复制这套分散实现。
- 用户确认 App 首版同时提供简体中文和英文；首次启动跟随 Android 系统语言，不支持的系统语言回退到简体中文，并允许在设置中手动覆盖。
- 用户明确首页不需要排行榜或成就在线摘要卡，也不保留空占位；排行榜从记录页或对局等明确入口打开，成就留在“我的”和结算反馈中。
- 用户确认 App 首版提供“跟随系统 / 浅色 / 深色”三种外观模式，默认跟随 Android 系统；手动选择后持久保存。
- 用户确认 App 保留 `2048 NEXT` 标志、青金品牌角色和现有数字块等级识别，其余页面、导航、按钮与弹窗全部采用专属移动端设计；首版只交付这一套品牌视觉的浅色/深色版本，不提供 Web 主题选择器或色板编辑器。
- 当前 Web 只有默认关闭、启用后才加载的循环背景音乐，两个编码文件分别约 3.2 MB 和 3.4 MB；代码扫描未发现正式的移动/合并音效或 Android 触觉反馈实现，因此 App 按已确认范围建设独立的平台反馈层。
- 用户确认 App 首版提供轻量操作/合并/里程碑/结束短音效与克制的系统触觉反馈，二者默认开启且可分别关闭；背景音乐保留但默认关闭。触觉不覆盖每次滑动，必须尊重 Android 系统触觉设置。
- 当前模式目录同时存在无撤回的 `standard_4x4_pow2_no_undo`（“标准版 4×4”）和可撤回的 `classic_4x4_pow2_undo`（“经典版 4×4”）；游客玩法已确定为前者。

## 基底原则

- App 是新的移动前端产品，拥有独立构建产物、路由、页面组件、设计系统和发布流程。
- 不整体加载现有 Web 的 HTML 页面、`playLegacyScripts` 或首页 legacy bundle。
- 游戏规则只能有一个权威实现；不得长期维护 Web 与 App 两套移动、出块、计分、撤回或回放语义。
- Web、App、小程序应消费同一份版本化游戏核心和数据契约，不得按端复制后各自演化规则。
- 跨端游戏核心必须无 DOM、无浏览器 storage、无音频和无页面导航依赖，并以输入动作产生可序列化状态与 effects。
- 平台能力通过窄适配层接入：安全存储、历史仓储、网络 outbox、生命周期、音频、文件分享和系统返回键。
- App 本地资源随安装包发布，不依赖远程网页才能启动；离线时标准本地对局和历史必须可用。
- App 页面、脚本、样式、字体和首局所需资源随 APK/AAB 发布，不需要单独部署移动前端服务器。
- 账号、排位、云记录、排行榜、成就同步和服务端回放验证继续依赖现有 `2048-game-api`；不得在 App 内复制后端权威。
- `2048-game-api` 的权威用户 ID 是三端数据关联主键；平台登录身份只能映射到该用户，不能成为第二套业务用户主键。
- 在线提交必须以 `client_record_id` 等稳定标识实现幂等，网络失败或鉴权过期不得静默丢失已结束对局。
- 所有本地数据结构必须版本化，并提供向前迁移或安全降级策略。
- 性能优化以可测指标为准，优先减少启动依赖、无效脚本、重复渲染和非必要资源预载，不提前引入复杂基础设施。
- 稳定性能力从基底开始建设：结构化错误、可追踪版本、崩溃/异常诊断边界、恢复测试和可重复构建。

## 初始需求

### 产品与导航

- 先完成 App 专属信息架构、关键任务流、页面线框和导航规则，再开始正式页面实现。
- 首版导航只承载玩家核心产品，不为暂缓的管理与工具能力预留空入口或占位页面。
- “记录”承载历史、回放及排行榜入口，“我的”承载账号、成就和基础设置；底部导航在顶层页面保持可见，在沉浸式、任务型和排行榜全屏模态流程中隐藏。
- 历史记录点击后进入详情页，详情页提供回放；排行榜独立模态窗口按首版三个模式切换，不把回放导入或独立回放库混入其中。
- 排行榜模态窗口只承载 2048 NEXT 自身的游戏排行榜，读取 `/leaderboard` 的分数/竞速数据；不得接入或展示独立 `2048-ranked` 产品的全国榜数据。
- 排行榜窗口提供总榜、日榜、周榜和月榜四周期选择，默认总榜；切换周期时只请求目标周期，并保留其他筛选和已加载结果的本地页面状态。
- 排行榜全屏模态顶部提供标题与关闭动作；Android 返回键优先关闭模态，关闭后精确返回打开它的来源页面，不重建来源页面或丢失状态。
- 对局页提供排行榜入口；打开时先持久化当前棋盘并屏蔽棋盘手势，计时、排位会话、后台保存和网络状态机不得暂停或重建。排行榜加载失败只能影响弹窗内容，不能影响当前对局。
- App 不显示首次启动轮播、首次对局遮罩、自动手势演示或“完成第一步”任务；模式名称和普通规则说明可以作为常规页面内容存在，但不得阻塞进入或操作棋盘。
- 首页有未完成对局时以“继续游戏”为唯一主操作，并显示最近退出存档的模式；否则以“开始标准 4×4”为唯一主操作。首屏以下只展示三个首版模式和最近记录，不展示排行榜、成就或其他在线摘要。
- 模式页可显示每个模式是否存在本地进度，但整张模式卡始终只负责进入模式，不让用户在进入前选择“继续 / 新游戏”。继续最近模式不得删除或覆盖其他模式的存档。
- 同一模式的“新游戏 / 重新开始”只允许在对局内部触发，并只替换该模式的当前存档；其他模式存档不受影响。
- 覆盖确认必须明确说明只清除当前模式进度；取消确认保持棋盘、计时、排位会话和存档不变。
- 首版不提供“主动结束并保存成绩”入口。离开未结束对局只返回首页并保留可继续存档；重新开始丢弃的对局不得生成记录、回放条目、排行榜成绩或成就进度，只有经游戏规则确认的真实终局才进入结算与历史链路。
- “待结算终局”期间不得提前写入本地/云历史、outbox、排行榜或成就；选择“撤回继续”恢复同一局，选择“结束并结算”才冻结终局和回放。应用离开或进程终止时持久化该待确认状态，恢复后仍显示同一选择，不得自动替用户结算或丢弃。
- 结算页不得等待云上传完成才能展示或离开；先以本地冻结记录立即呈现，上传成功、待同步或失败状态原位异步更新。“再来一局”直接创建同一模式新局，“查看回放”打开刚冻结的回放，“返回首页”清除该模式已结算存档并返回首页。
- 首版结算页不重复提供模式选择、排行榜或其他大厅入口；这些能力继续由既定模式页、记录页和排行榜全屏模态承载。
- 活动中的半局不得导出或分享；App 不展示、复制原始回放代码，也不同时维护 Web 的 `.txt` 与历史 `.json` 两套移动导出入口。首版不提供公开回放链接或外部回放文件导入，版本化文件契约必须保留未来兼容读取空间。
- 首页主体完全依靠本地状态立即呈现，不为排行榜或成就发起摘要请求；网络失败不得阻塞开始、继续或查看本地最近记录。
- 游客可以浏览首版模式目录；除 `standard_4x4_pow2_no_undo` 外，点击其他模式时进入登录引导，登录成功后返回原目标模式。
- 游客玩法必须可离线开始、继续和结束；登录门槛不得使 App 冷启动依赖服务器。
- 首版模式目录只展示已交付的三个模式，不为斐波那契、大棋盘或特殊规则显示不可用占位入口。
- 游客局不进入权威排行榜或成就统计；同一设备登录后仍可查看本地游客记录，但不得把它们改写为账号云记录。
- 已登录离线对局保留稳定 `client_record_id` 并进入上传 outbox；恢复网络和有效鉴权后提交为普通云历史，不得补录为排位成绩或触发排位成就。
- 开始按钮不拆分“普通 / 排位”两个入口；对局页必须在开始前和进行中清楚显示“排位”或“离线对局”状态。
- 游戏页面使用沉浸式全屏流程，不受 Web 顶部操作区和多 HTML 入口限制。
- 首次合成 2048 不作为对局结算点，不暂停或重置计时、排位会话、存档和输入；App 显示短暂里程碑反馈后继续当前局，只有真正满足模式结束条件时才进入结算。
- Android 系统返回键、前后台切换、进程终止恢复、状态栏和安全区必须是正式交互的一部分。
- 前台/后台切换不得重建棋盘；进程终止恢复不得自动把用户跳入旧局，也不得丢失最后一次已持久化动作后的状态。
- Android Activity 使用竖屏方向策略；旋转手机不得触发页面横屏重排或导致当前对局重建丢失。
- 正式页面验收宽度以 320–480dp 手机竖屏为主；大屏设备不得崩溃或遮挡关键操作，但不进入首版专属布局验收。
- 页面和能力按首屏、对局必需、按需加载三档划分，非首局能力不得阻塞冷启动。
- App 文案使用移动端自己的集中式中英文字典，页面和组件不得直接依赖 Web 的 `UII18N`、`ui_language_v1` 或散落 legacy copy；语言切换不需要重新启动 App，也不得丢失当前导航与对局状态。
- 浅色和深色必须由同一套语义化设计 Token 驱动，不复制页面或加载两套组件；跟随系统时响应 Android 外观变化，切换不得重建棋盘、重置导航或触发网络刷新。
- App 视觉使用一套移动端语义 Token 和组件层级；青金色只承担品牌、选中、里程碑和关键操作，数字块保留稳定等级识别。不得引入 Web 主题运行时、主题选择器、自定义色板或页面私有视觉拼装。
- 声音与触觉只消费游戏核心产生的 effects，不得反向参与移动、计分、出块或回放状态；“音效 / 触觉 / 背景音乐”在设置中独立控制。App 失去音频焦点或进入后台时暂停背景音乐，短音效不得与其他应用争抢持续音频焦点。
- Android 安装包只携带一种经过验证的背景音乐压缩格式，不同时打包 Web 的 OGG 与 M4A；音效使用短小本地资源，背景音乐默认不解码进内存，直到用户主动开启。
- 正式签名密钥不得进入仓库或普通 CI 日志；官网 APK 与 AAB 必须来自同一版本源码和稳定签名身份。官网公布版本号、文件大小与 SHA-256，不申请静默安装、未知来源安装或自更新权限。
- 首版不得注册设备推送 Token、通知渠道或后台通知任务，Android 清单不声明 `POST_NOTIFICATIONS`；同步、成就和网络反馈必须在 App 当前界面内完成。账号删除等关键状态通过页面与邮箱确认，不依赖系统通知。

### 技术边界

- Capacitor 只承担 Android 容器与原生能力桥接；不得把线上网站地址作为 App 的主运行内容。
- App 使用独立的 Vite + TypeScript 构建和移动端源码边界，不复用现有 Web 多页面入口；首版使用原生 DOM/CSS 能力，不引入额外 UI 框架。
- 先用标准 4×4 模式验证无 DOM 核心，再扩展撤回、回放、排位和特殊模式。
- 同一初始棋盘、seed 和动作序列必须在 Web 兼容路径、App 核心和服务端回放验证之间产生一致结果。
- API 契约应由后端权威维护，移动 MVP 使用的路由、方法、请求体、错误码和兼容策略必须冻结并测试。
- App 账号页直接使用 `/login`、`/register/start`、`/register/verify`、`/auth/refresh` 和密码重置契约，不加载 `/access/me` 或 beta notice 作为玩家准入条件。

### 三端共享与同步

- Web、App、小程序分别拥有独立页面和平台适配层，但共享无 DOM 游戏核心、API 契约、模式标识、回放格式和服务端验证语义。
- 账号资料、云端验证记录、回放、排行榜、成就及明确标记为云同步的设置以 `2048-game-api` 为权威来源。
- Token、安全凭据、本地缓存、待上传队列、设备布局偏好和安装级状态不得在三端直接互传；它们由各端安全管理。
- 未结束对局和本地历史不进行首版跨端续接；服务端排位 checkpoint 仅用于排位可靠性和验证，不得在 App UI 中承诺另一设备可接续同一棋盘。
- 所有跨端写入必须具备稳定客户端记录 ID、幂等语义、服务端版本或冲突规则，避免多设备重复提交或静默覆盖。
- 三端版本可独立发布；后端 API 和共享数据 schema 必须保持已发布客户端可继续运行的兼容窗口。
- 小程序必须通过微信合法域名调用同一 HTTPS API，不新增小程序专用数据库或排行榜。
- 微信身份绑定方案不属于当前 Android 首版阻塞项，留待小程序阶段在统一用户 ID 原则下单独决策。

### 数据与可靠性

- Token 不得只存放在普通 WebView localStorage；必须使用 Android 安全存储边界。
- 本地对局、设置、历史、待上传结果和 schema 版本必须有明确仓储所有者。
- Web 本地历史不属于 App 首版迁移输入；现有导出/导入契约可在后续版本用于显式手动迁移，但不得进入首版启动路径。
- App 进入后台、被系统回收或网络中断时，当前局和已结束结果必须可恢复。
- 上传 outbox 必须区分成功、永久业务拒绝、鉴权失效、限流和临时网络/服务端错误。
- 退出账号是账号本地数据的清除边界。由于 Android Keystore 与 IndexedDB 无法共享物理事务，产品要求是“逻辑原子清除”：一旦进入确认清除流程，就先持久化清理中状态、停止该 owner 同步并令其全部数据立即不可见，再删除 Token、账号缓存、该账号未结束存档和 outbox；任一步被强杀后必须在下次启动继续清理，不能留下可被下一账号读取或上传的孤立数据。
- 退出确认后的原子清除只有在用户明确选择破坏性操作后执行；上传成功的条目先从 outbox 移除，提示数量必须基于清除事务前的最终状态重新计算。
- 回放文件的服务端备份、恢复、容量和告警属于移动公开发布前的后端稳定性门槛。
- “我的”必须提供隐私政策、用户协议和账号删除入口；同时提供无需安装 App 即可访问的账号删除网页。申请删除必须重新验证身份，写入服务端 `deletion_requested_at` 与 `deletion_due_at`，并立即撤销既有 Token、暂停 outbox 和退出账号。
- App 安装包内提供当前版本的隐私政策与用户协议正文，同时保留公开网页链接；首次选择记录已同意的政策版本。只有政策发生实质变化才重新请求确认，不能用普通文案更新反复打断用户。
- “仅离线体验”状态允许本地游客对局、存档、历史、外观、语言、音效和触觉设置；登录注册、排行榜、云历史、成就同步及其他联网入口必须先完成隐私同意。未同意状态不得静默联网探活、上传日志或发送遥测。
- 云历史快照只保存用户实际加载过的有限页面，成就保存轻量摘要，回放正文只在用户查看后按需缓存；所有快照绑定产生它的用户 ID 和缓存版本。离线快照不允许删除、恢复或修改云端状态。
- 账号云记录只能联网删除；删除后立即退出活动历史、排行榜和相关统计，进入“最近删除”并显示恢复截止时间，恢复后由服务端重新计算。游客本地记录删除前必须说明不可恢复，确认后原子删除记录及其本地回放数据，不影响云数据。
- 成就契约必须显式描述可完成客户端或所需模式；App “已获得”视图不按客户端过滤，“未获得/可挑战”视图只显示首版 App 可完成项。来自 Web 的已获得成就可显示跨端来源标签，隐藏成就未获得前不得泄露名称、说明或图标。
- 冷静期内账号资料、云历史、回放、排行榜和成就保留但从公开页面隐藏；只有重新输入邮箱和密码并在 `deletion_due_at` 之前成功登录，才原子取消待删除状态并恢复公开数据。后台 Token 刷新、自动登录或普通 API 请求不得取消删除。
- 到达 `deletion_due_at` 后，即使清理任务尚未运行也不得再取消删除或登录；清理任务彻底删除账号资料、云历史、回放、排行榜和成就，不保留匿名成绩，只保留法律或安全审计要求的最小日志。
- 待删除账号的邮箱在冷静期内保持占用；最终清理完成后允许使用同一邮箱重新注册，但必须生成全新用户 ID，不得恢复、关联或继承旧账号的资料、记录、回放、排行榜、成就或其他数据。
- 崩溃与严重错误诊断采用字段白名单和发送前脱敏，只包含定位稳定性问题所需的错误类别/堆栈、App 版本与构建号、Android/WebView 环境和发生时间等最小技术信息；服务端接口必须限制载荷大小、速率和保留周期，不得把诊断数据并入玩家画像或排行榜业务数据。
- 自动诊断只有在用户同意联网且设置开关开启时才能发送；关闭后不再上传新诊断，未同意隐私的离线体验状态不得初始化或探活诊断服务。无法上传时不得阻塞启动、对局、存档或退出；用户可手动导出本地诊断包自行提供给维护者。

### 性能与质量

- 首页、模式、记录、我的等普通页面切换以及游客标准 4×4 对局不得等待服务器；在线数据应在页面立即呈现后异步刷新。只有排位 session start 等强在线操作可以在棋盘展示前显式等待网络；棋盘标记为可操作后，任何滑动和动画首帧都不得再等待网络。
- 建立冷启动、首个可交互页面、进入游戏、移动响应和动画帧稳定性的基线与预算。
- 棋盘动画优先使用 `transform` 和 `opacity`，不得通过持续布局抖动驱动动画。
- 动画必须使用 `requestAnimationFrame` 时间戳和基于时间的进度，不得硬编码 16.67ms 帧长或把逻辑绑定到 60 FPS；高刷设备应能跟随系统实际刷新率。
- release 构建性能预算：中端手机冷启动至首页可操作不超过 2 秒；Android 10、4GB 基准机不超过 3 秒；顶层导航响应不超过 100ms；首页进入本地对局不超过 500ms；滑动输入到棋盘首帧响应不超过 50ms。
- 60Hz 设备以稳定 60 FPS 为目标且不得持续低于 50 FPS；90/120Hz 设备必须实际使用系统高刷节奏，不得被应用固定封顶在 60 FPS。
- 首版性能矩阵至少包含 Android 10/4GB 低端真机、90Hz 或 120Hz 主流中端真机、最新稳定 Android 模拟器，以及 320/360/412/480dp 四种手机竖屏宽度。
- 图片、字体和音频按使用时机加载；大体积 BGM 不进入首屏关键路径。
- 单元测试覆盖纯核心和数据迁移；集成测试覆盖生命周期、outbox 和 API；Android 模拟器/真机覆盖关键任务流。
- CI 必须能重复产出可安装的 debug APK、官网 release APK 和商店兼容 release AAB，并运行基底质量门禁；正式签名注入与源码构建隔离。
- debug 与 release 构建共享 `cn.next2048.app` 产品身份规则，但开发环境不得覆盖正式安装数据；具体 debug 后缀在技术设计中确定。
- Android 10 是兼容性下界，不为 Android 9 及以下增加旧 WebView、存储或生命周期兼容分支。

## 初始验收标准

- App 可从本地安装资源冷启动，不依赖加载线上网页。
- 断网时仍可进入本地页面并开始或继续游客标准 4×4；普通页面导航不得因 API 不可用而阻塞。
- App 构建不包含现有 `playLegacyScripts` 全量清单或 Web 首页 legacy bundle。
- 首次启动选择“仅离线体验”后可在无网络环境进入首页并完成游客标准 4×4，对局期间没有业务网络请求；首次点击任一联网入口会显示同一版本的隐私选择，取消后返回原页面且不联网。
- 标准 4×4 对局在断网状态下可开始、继续、结束并写入本地历史。
- 未登录用户只能开始已确认的 4×4 游客玩法；其他模式显示清晰的登录门槛，且登录成功后恢复原选择。
- 登录用户可以开始 `standard_4x4_pow2_no_undo`、`classic_4x4_pow2_undo` 和 `board_3x3_pow2_no_undo`，三者均通过同一无 DOM 核心、存档和回放链路运行。
- 游客完成的对局不得生成排位排行榜记录。
- 登录不会删除本地游客历史，也不会把游客记录上传、计入账号排行榜或成就；登录后完成的新记录按账号同步规则处理。
- 已登录用户断网时可开始和完成三个首版模式；离线结果恢复网络后只产生一条普通云记录，重复重试不得进入排行榜或重复入库。
- ranked session start 使用稳定 operation ID；响应丢失、重试或准备阶段强杀后不得创建多个活动 session，也不得展示半初始化棋盘。同一 operation 返回相同 `started_at/seed/token`；安全存储失败或有界准备失败时只进入 normal 局。ranked 棋盘显示后计时已从服务端锚点连续运行，但首个滑动到动画首帧仍满足本地 ≤50ms 预算。
- 已登录用户断网打开记录或成就时，存在快照则显示内容、离线状态和最后更新时间；无快照则显示明确离线空状态。恢复网络并刷新成功后原位更新，不重复记录或丢失滚动位置。
- 云记录删除后可在 3 天内从“最近删除”恢复，超过服务端截止时间后不可恢复；游客记录删除确认后立即从列表与本地存储消失，重启 App 也不会恢复。离线状态不显示可执行的云删除/恢复动作。
- App 登录同一账号后能看到 Web 已获得的成就；Web 专属或未移植模式的未获得成就不出现在可挑战列表。隐藏成就获得前无可识别占位，获得后在已获得列表与离线快照中正常显示。
- 新安装 App 不读取 Web 浏览器本地历史；登录账号后可以读取服务端已有云记录，且不会因此产生重复本地记录。
- 固定 seed 与动作序列的最终棋盘、分数、出块和回放在兼容 Web 路径、App 核心和服务端验证之间一致。
- Android 后台切换和进程重启后可恢复未结束对局；已结束但未上传的结果不会丢失。
- 同进程后台恢复直接回到对局；冷启动进入首页且“继续游戏”可恢复此前模式、棋盘、分数、计时与排位/离线状态。
- 登录、当前用户、排位会话、记录提交和排行榜读取均通过固定 Node/PostgreSQL API 基址完成。
- 新邮箱无需邀请即可在 App 完成验证码注册、登录并进入登录专属模式；流程中不出现“内测资格”或“受邀邮箱”提示。
- 用户可在 App 内发起账号删除，并能通过公开网页了解或发起同等流程；删除后旧 Token 失效且不能继续写入数据。
- 申请删除后 App 立即回到游客状态并显示删除截止时间；72 小时内凭邮箱密码登录会明确提示“已取消账号删除”。超过截止时间的登录按账号已删除处理。
- 待删除期间其他设备的旧 Token、后台同步和 outbox 重试均不能取消删除或写入新数据；取消删除后只有原账号的 outbox 才可恢复。
- 正常退出后重新登录同一账号也不会恢复此前被清除的本地未结束对局或 outbox，只能重新读取已存在的云端数据。
- 无账号本地存档且 outbox 为空时可直接退出；存在数据时，取消退出必须保持 Token、存档和 outbox 完整不变，确认退出后旧 owner 必须立即整体不可见并最终全部清除。模拟清理任一步骤被强杀后，重启必须先续清且下一账号始终不可读取或上传旧 owner 数据。
- 最终清理后个人资料、普通/排位记录、回放对象、排行榜索引、成就和待上传服务端状态均不可查询，排行榜按剩余记录重新计算。
- 最终清理完成前同一邮箱注册必须被拒绝；完成后可通过正常验证码流程注册全新账号，新账号具有新的用户 ID 且查询不到任何旧账号数据。
- 同一权威用户登录 Web、App 和小程序后，可以读取一致的云记录、排行榜身份、成就和账号资料。
- 同一账号在另一设备登录时看不到当前设备尚未结束的棋盘；两台设备各自的本地活动对局不得互相覆盖。
- 三端对同一已结束对局重复提交时，服务端只产生一份权威记录；冲突和失败状态可诊断。
- 任一客户端停留在兼容窗口内的旧版本时，其他客户端和后端发布不得破坏其基础登录、读取和记录提交流程。
- 安全存储中不存在明文落入普通 localStorage 的权威 Token。
- 320dp 级窄屏、常见手机竖屏宽度、状态栏和底部手势区域均无关键控件遮挡；旋转手机后仍保持竖屏体验和当前状态。
- Android 返回键行为有明确层级：先关闭临时层、再返回上级页面、根页面才退出。
- 首页、模式、记录和我的可通过四项底部导航单次点击切换；对局、结算、回放和登录注册页面不显示该导航。
- “记录”页打开排行榜时不得在原页面内展开或挤压历史列表；关闭排行榜后恢复原历史滚动位置和筛选状态。从历史详情启动回放后隐藏底部导航，退出回放返回原历史位置。
- 排行榜全屏模态显示时底部导航不可见；点击顶部关闭或按 Android 返回键均只关闭排行榜，并恢复来源页面原有状态。
- 对局中打开排行榜后，继续经过的时间必须计入当前局；弹窗期间的触摸不得移动棋盘，关闭后第一下有效滑动只执行一次游戏动作。
- 2048 NEXT 排行榜窗口只请求 `/leaderboard` 的 `score` 或 `speed`；历史和个人记录的盘面和排序只使用记录查询的 `sort_by=board_sum`，两种语义不得混用。
- 分数榜必须由后端按“分数降序、首次取得该分数的 `ended_at` 升序、稳定用户 ID 升序”返回唯一连续名次；同一用户多次取得相同最高分时采用最早一局，数据重建不得改变既有先后，Web 与 App 不得自行按数组下标推测不同名次。
- 竞速榜必须由后端按“目标方块毫秒时间升序、首次取得该时间的 `ended_at` 升序、稳定用户 ID 升序”返回唯一连续名次；同一用户多次取得相同最佳时间时采用最早一局，整局用时和步数不得改变同竞速成绩的公开先后。
- 历史 ranked 数据迁移必须输出可信 begin、服务端接收 fallback 和异常三类审计；缺少可信锚点的旧记录只可使用已冻结的服务端接收 fallback，不能使用客户端旧时间。回填前后保留旧榜快照并核对记录数、用户最佳、周期边界和榜单重建结果，异常时停止上线且不破坏原始记录。
- 首页在无网络时仍能呈现主操作和首版模式；存在多个未结束模式时，继续入口准确指向 `last_closed_at` 最新的存档，并显示正确模式与分数。
- 点击任一模式卡后，有存档时直接恢复对应棋盘、分数、计时和排位/离线状态；无存档时直接创建该模式新局，全程不出现外部“继续 / 新游戏”选择层。
- 有有效移动的未结算对局点击重新开始时出现一次确认；无有效移动或已结算时不显示冗余确认，且任何重新开始都不影响其他模式存档。
- 未结束对局按 Android 返回键后，首页可继续恢复同一棋盘且历史列表没有新增记录；确认重新开始后只有当前模式存档被新局替换，本地历史、云历史和 outbox 均没有被放弃局产生的条目。
- 经典可撤回模式无路可走且存在可撤回状态时，历史和 outbox 保持不变；撤回后可继续产生合法动作，选择结算后只生成一条冻结终局记录。无可撤回状态及两个无撤回模式不会停留在该选择层。
- 真实终局冻结后结算页在本地立即可见，断网或上传失败不阻塞“再来一局”“查看回放”或“返回首页”；重复点击或页面恢复不得生成第二条记录。“再来一局”保持当前模式，其他模式存档不受影响。
- 已结算记录从结算页、历史详情和回放播放器发起分享时生成相同格式与内容的版本化文件；Android 分享或保存取消后原页面状态不变。未结束存档没有分享入口，导出文件不包含 Token、邮箱或其他账号凭据。
- 性能预算、错误分类、本地 schema 迁移、API 兼容和发布回滚均有自动化验证或可执行检查。
- debug APK、官网 release APK 与商店 release AAB 可由干净环境重复构建，密钥和生产配置不进入仓库。
- 官网 release APK 的版本号、SHA-256 与发布记录一致；使用同一签名安装新版可覆盖升级且保留本地数据，使用错误签名的包无法覆盖正式安装。
- debug APK 可在 Android 10（API 29）设备或模拟器安装、冷启动、离线开始游客局并完成后台恢复。
- release 构建满足冷启动、导航、进入对局和输入响应预算；在系统高刷已启用且未受省电或温控限制的 90Hz+ 真机上，棋盘动画不存在应用侧 60 FPS 封顶。
- 简体中文系统首次启动显示中文，英文系统首次启动显示英文，其他系统语言回退中文；手动切换后重启仍保持选择，并且 320dp 宽度下两种语言都不遮挡关键操作。
- 跟随系统模式在浅色与深色系统环境下显示对应外观；手动浅色或深色不受系统切换影响。所有首版页面、弹窗、底部导航和棋盘文字均满足可读性与对比度要求，切换过程中不出现白屏闪烁。
- 浅色与深色下的品牌标志、棋盘、数字块、主操作和状态颜色语义一致；移除 Web 主题/色板运行时后仍可独立渲染所有首版页面，不加载任何 Web 页面样式清单。
- 音效、触觉和背景音乐三个开关可独立持久化；关闭任一项立即停止对应反馈。系统关闭触觉时 App 不强制震动，进入后台或失去音频焦点时音乐暂停，返回前台后按用户设置安全恢复。
- 首次安装和升级后均不会弹出 Android 通知权限请求；离线、同步失败、成就解锁和账号状态在 App 内有可感知但不阻塞游戏的反馈。
- 首次进入任一模式时直接显示可操作棋盘，不出现教程遮罩或自动提示；首个滑动按正常游戏输入处理，不额外修改计时、排位或存档状态。
- 首次合成 2048 时不会出现要求点击“继续游戏”的遮罩；里程碑提示不会吞掉下一次滑动，对局计时和排位会话连续，当前局仍可继续合成更高方块。
- 选择“仅离线体验”并完成多次对局后，服务端仍收不到任何诊断请求；完成隐私同意后，模拟崩溃或严重错误只上传字段白名单内的脱敏技术信息，载荷中不存在邮箱、昵称、Token、棋盘、回放或移动序列。
- 关闭“自动发送诊断”后模拟同类错误不会联网提交，且用户仍可从设置中导出可读的本地诊断；诊断接口不可用或限流时，App 的启动、对局、存档和退出仍可正常完成。

## 暂定范围外

- iOS App 和微信小程序实现；本规划只要求共享边界不阻塞未来接入。
- 平板、折叠屏和横屏的专属导航、双栏页面或棋盘布局。
- 微信登录、`openid/unionid` 绑定和小程序页面设计延后到 Android App 稳定后的独立规划。
- 直接迁移现有 Web 页面视觉或保持 Web/App 页面一一对应。
- Web 浏览器 localStorage/IndexedDB 历史的自动迁移及手动文件导入界面。
- Web 与 App 之间的未结束对局续玩及通用云存档冲突合并。
- 在规划阶段重写现有 Web 全部页面或一次性删除所有 legacy 脚本。
- 新建移动专用后端、复制账号系统或绕过服务端回放验证。
- 首版不包含管理后台、接力工具、2K 监控、完整色板编辑器和实验模式。
- 首版不包含商店专属登录、计费、推送、强制更新或应用内 APK 安装框架。
- 首版不包含系统推送、本地提醒、每日召回、通知渠道或后台常驻通知服务。
- 首版不包含首次启动功能轮播、首次对局教程、自动手势演示或强制教学任务。
- 首版不包含 Sentry、Crashlytics、广告归因、页面点击埋点、游戏行为分析或其他第三方统计 SDK。
- `2048-ranked` 的全国榜、板块、投稿、审核、内容和管理能力不进入 App；共享账号后端不改变两个产品的边界。
- 斐波那契、4×2/4×3、5×5 及以上棋盘、八方向、封顶、障碍、道具、石头、限时等模式延后增量加入。
