# 长对局存储与终局数据完整性修复

## 背景

生产现场显示浏览器 `localStorage` 已接近配额上限。主要空间由同一长对局的完整存档、轻量存档和 checkpoint 本地镜像重复占用，本地历史又把 IndexedDB 数据完整镜像回 `localStorage`。关键写入失败时，现有终局流程仍会清除当前对局、checkpoint 和会话引用，导致本地记录、云端待上传记录与恢复来源同时丢失。

普通站内导航（包括进入练习板）还会被错误转换成 `abandon/navigation`，既违反既有产品语义，也会在 attempt outbox 写入失败时阻止正常导航。

## 目标

- 普通站内导航不产生 `abandon`，不阻止进入练习板。
- 只有明确重新开始或明确放弃并清除存档才产生 `abandon`。
- 本地历史或云端待上传记录未可靠保存时，不清除当前对局的恢复来源。
- `localStorage` 配额异常必须成为可判断的失败结果，不能被当成成功。
- IndexedDB 可用时，完整本地历史不再长期重复保存在 `localStorage`。
- 同一当前对局不再同时持有完整存档和冗余轻量存档；checkpoint 本地镜像不再嵌套另一份完整存档。
- 已有存档、历史和待上传数据采用先迁移/验证、后清理的兼容路径。

## 非目标

- 不修改服务端排行榜校验规则或 API 合同。
- 不删除用户仍可恢复的当前对局或历史记录。
- 不新增依赖，不重写整个存储层。
- 不把历史内部变量名扩张为新的产品模式概念。

## 验收标准

1. 模拟 `QuotaExceededError` 时，本地历史保存不得返回假成功。
2. 云端待上传记录写入失败时，不清除当前存档、checkpoint 或当前会话引用，也不把记录标记为已提交。
3. 本地历史可靠保存后才允许继续终局清理流程；异步保存失败时可再次尝试。
4. 完整存档写入成功后，同模式冗余轻量键被删除；完整存档失败时轻量存档仍可作为回退。
5. checkpoint 本地镜像保留可恢复的紧凑回放和计时信息，但不包含 `ui_state.saved_state` 完整副本。
6. IndexedDB 迁移成功并验证后，旧 `local_game_history_v1` 镜像可被清除；IndexedDB 不可用时仍保留本地回退，回退写入失败必须显式失败。
7. 点击练习板、模式列表、设置、用户入口或标题链接均不产生 `abandon`；明确重新开始的既有合同保持通过。
