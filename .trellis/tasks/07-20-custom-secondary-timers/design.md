# 自定义子计时器设计

## 边界

- 纯规则层负责解析、校验、规范化、棋盘进度比较和命中类型判定。
- 现有 GameManager 子计时器层继续负责动态 DOM 行、展开、时间写入、存档采集和恢复。
- 设置层只负责编辑“下一局规则”并按 ruleset family 写入本地存储；编辑器归属 `palette.html` 设置页的计时器分类，使用原生 `details` 保持默认收起。
- 设置页预览复用同一解析结果、`timertile` 视觉类和主题同步；只渲染已保存文本，母计时器按钮管理其子规则的本地展开状态，不参与游戏计时状态。

## 数据契约

- `GameManager.TIMER_SLOT_IDS` 在应用模式配置时根据 ruleset、棋盘尺寸和显式 `max_tile` 重建，不再是全局固定的 12 项。
- Fibonacci 容量按第 `2 * cells` 个可合成数计算；计时器展示通常包含该理论最大值，4x4 例外地截在前一项。
- 练习板摆盘上限直接读取同一套 Fibonacci 计时器里程碑终点，避免理论容量、计时器和预选块各自维护不同上限。
- 现有 HTML 中的低阶母计时器行继续复用；超出静态 HTML 的槽位由 setup 运行时按需创建。
- 规范化规则保留：母计时器值、完整方块序列、规范化表达式和显示顺序。
- 动态行以表达式末项作为可见图例，以 `values.length - 1` 作为缩进层级；完整表达式继续用于 DOM 身份、标题、命中、覆盖和存档。
- 在局快照保留规范化规则，不读取随后变化的设置值。
- 子计时器状态在现有 `timer_secondary_rows` 基础上增加规则表达式、命中类型和覆盖来源；旧 parent/child 状态继续兼容读取。

## 进度比较

- 精确命中先使用方块计数包含关系；扣除表达式要求后，额外方块不得高于表达式的最小项，因此 `32+16+2+2` 仍精确，而 `32+16+4+2` 会进入覆盖判断。
- 覆盖使用降序方块序列的逐项比较；第一个不同位置的实际值更大即表示进入更高进度。
- 实际值更小或相同前缀后实际序列先结束时，不构成覆盖。
- 精确命中优先于覆盖，避免额外小方块把真实组合误标为越级。

## 运行时顺序

1. 玩家在设置页展开计时器分类，选择 2 的幂或 Fibonacci 规则体系；可手写规则，也可选择母计时器起止范围生成推荐规则。
2. 推荐生成器对每个母计时器 `P` 写入分组头，再写入 `P+子值`；随后取最大的合法子值 `L`，写入 `P+L+更小子值`。只生成这两层常用关键节点，不穷举全部组合。
3. 生成文本替换输入框但不触发存储；玩家检查后仍通过现有保存按钮完成校验和持久化。
4. 新局 setup 时从 ruleset family 配置创建在局规则快照并生成动态行。
5. 应用模式配置时先更新母计时器槽位与里程碑，设置校验和子行定位共享这份当前模式列表。
6. 每次成功移动完成随机/强制生成后读取棋盘值。
7. 纯规则层一次性返回所有首次命中的规则及 exact/covered 元数据。
8. 现有计时器层写入时间与标记，再走现有刷新、存档和滚动流程。

计时值继续使用现有全局用时里程碑，不在本次改为父子节点之间的阶段耗时差。

## 兼容与迁移

- 不迁移旧固定子计时器为默认配置；升级后空配置即没有子计时器。
- 恢复含旧 `timer_secondary_rows` 的存档时继续容错，不让旧存档阻断启动。
- 本功能仅使用浏览器本地存储，不触碰 API 边界。
- 现代模块入口是当前功能实现与验证范围；仓库保留的 `nomodule` 加载器按现有架构守则属于独立 legacy-browser policy，不在本任务中扩张其能力。

## 回滚

- 删除新的配置键和在局规则字段即可回到无动态子计时器状态；母计时器不受影响。
